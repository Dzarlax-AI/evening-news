# Go/Cloak: накопленные изменения для ревью

Срез от 2026-10-21. Ветка `codex/go-cloak-mac-handoff`, база
`c9441de4a6e0314a3c7073158ac960de11b9b4d3`. Это локальный пакет для ревью;
коммит, PR, публикация образов и включение в production не выполнены.

## Что смотреть

| Часть | Изменение и цель | Приёмка |
|---|---|---|
| Go CDP transport | Фильтрация событий до очереди, ограниченные асинхронные RPC, отдельные allocation/cleanup receipts. Обработка событий не ждёт синхронно ответ на каждую команду. | Fake-CDP и race; native Linux gate. |
| Изоляция crash | Подтверждённый crash своей вкладки завершает одно задание пустой ошибкой. Продолжение разрешено после cleanup, проверки отсутствия своих ресурсов и живого неизменившегося браузера. Неопределённая потеря ownership остаётся terminal. | Финальный Linux gate: crash → готовность → успех следующего задания; overflow → отказ без нового allocation. |
| Go API/декодирование | Ограниченное чтение одного JSON, запрет неизвестных полей и trailing data; readiness и доступность различаются. | Service/decoder/runtime regression tests. |
| Python очередь | Crash не считается окончательным отказом статьи. Существующая очередь назначает отложенный повтор с прежним лимитом попыток; немедленный replay и Python fallback запрещены. | Запись состояния в изолированную БД, пропуск недоспевшего повтора, успех позже, exhaustion и прогресс соседней статьи. |
| Python качество | Полная форма выбора подписки отбрасывается тем же узким правилом, которое уже было в Go. | Сохранённый результат case-0041 и synthetic positive/negative regressions. |
| Изолированный стенд | Linux runner, synthetic soak, CDP relay, контролируемый crash helper и проверки owned cleanup/provenance. | Локальные тесты; сохранённые native receipts. Это экспериментальная инфраструктура проверки. |
| Документация | Планы и хронологические handoff-записи, включая неудачные попытки. | Актуальные выводы собраны в этом документе; старые статусы в истории не являются текущей приёмкой. |

## Свежие локальные проверки

- `cd go && GOPROXY=off go test -race -count=1 ./...`: все девять пакетов прошли.
- `cd go && GOPROXY=off go vet ./...`: завершён без замечаний.
- Затронутые extraction, queue и stand suites: **556 tests + 16 subtests passed**.
  Остаются предупреждения deprecation Pydantic/datetime; они не исправлялись в этом объёме.
- 54 входных файла Go-сборки (исходники, тесты, go.mod и go.sum) побайтно
  соответствуют source manifest финальной Linux-сборки.
- Luna выполнила ограниченное статическое ревью runtime, decoder и двух Python
  изменений; блокирующей ошибки не выявлено. Это не полный аудит сетевого стенда
  и не доказательство production readiness.

## Ограничения перед решением о включении

1. Полное совпадение извлечения и production readiness не приняты. В старой
   live-серии были HTTP403, resource limit и timeout/crash. Успех одной статьи
   и продолжение очереди не означают успешного извлечения всех пяти.
2. Case-0041 был ложным успехом Python: 1433 символа формы подписки.
   Офлайн Go также отклонил сохранённый B HTML. HTML конкретного C-запроса
   не сохранялся; тождество двух DOM не доказано. Исправление фильтрует форму,
   а не извлекает недоступный текст статьи.
3. Ресурсная ёмкость строго не принята. Финальный gate шёл в диагностическом
   режиме: превышения working-set budget не было, но PSI-порог наблюдался
   с 31 bypass sample. Это не основание повышать лимиты или обещать запас VPS.
4. Падения Chromium и прежний редкий relay TCP timeout не объяснены полностью.
   Изоляция сбоя устраняет остановку следующих заданий, но не причину crash.
5. Ранее отклонённые статьи автоматически не переводятся обратно в очередь.
   Новые delayed retries подчиняются существующим настройкам, фильтрам дат и
   запуску processing cycle.
6. Go backend по умолчанию выключен (`EXTRACTION_SERVICE_MODE=python`).
   Конфигурация production в рамках подготовки этого пакета не менялась.

Последние сохранённые независимые production postchecks подтверждают неизменные
fingerprints/health/max/OOM и рабочие home/feed, а также удаление owned стенда.
При подготовке первоначального пакета новых VPS-проверок и обращений к
издателям не было; результаты последующего согласованного прогона приведены ниже.

## Дополнение: контрольный прогон выполнен

После этого среза пользователь разрешил контрольную серию. Для неё стенд получил
только дополнительную read-only подмену `extraction_utils.py` (проверена отдельным
тестом); runtime Go не менялся. Пакет ревью обновлён с этим изменением.
Финальный кандидат выполнил B5/C5 без дублей: 592.9 секунды, успешное извлечение
одной статьи у каждой версии. Go продолжил после live crash предпоследней
статьи и успешно извлёк последнюю. Точное распределение исходов и ограничения:
`artifacts/final-control-live-2026-10-21/result.json`.

Полная quality parity и строгая ресурсная ёмкость не приняты; в диагностике есть
PSI bypass и единичный relay connect timeout. Production и очистка независимо
проверены. Включение Go в production этим прогоном не выполнено и не разрешено.


## Этап закрыт

Пользователь согласовал завершение этого этапа после контрольного прогона.
Самостоятельный Go extractor и изоляция crash реализованы; подтверждённого
преимущества по извлечению перед Python на выбранной пятёрке нет. Накопленные
изменения и доказательства сохраняются локально, без переключения production.
Разработка стенда, новые прогоны и автоматические попытки улучшать проблемные
сайты прекращены в рамках этой работы. Код не сбрасывался; commit/push/PR и
публикация образов не выполнялись.

Пользователь потребовал довести экстрактор до production-quality. Закрытие
экспериментальной серии не означает завершения этой цели. Подготовлена native
