# Web API components

`go-web` owns the public and admin HTTP routes, templates, authentication, job acceptance and schedule management. The private Go domain serves authenticated domain and AI callbacks. Worker, ingestion, processing and scheduler components run in the existing Go background process. Internal listeners are not published as public routes.

The web receives database, authentication, scheduler and private-backend credentials; provider credentials stay in the domain. `WEB_BACKEND_URL` is the domain origin and `WEB_BACKEND_TOKEN` is separate from job and AI tokens. The explicit `/usr/local/bin/news-migrate` command runs once before schema-dependent services start. Web startup checks schema readiness and does not apply DDL.

The frozen public API contract is in `go-web/contracts/openapi.json`. Run `go test -race ./...` and `go vet ./...` in `go-web`, and the private backend and migration tests in `go-domain`. Database tests require an isolated loopback `TEST_DATABASE_URL`. The consolidated synthetic image gate covers public/admin authentication, source management and the real job pipeline. See [Private Go domain runtime](go-domain-runtime.md) and [Core image build and release](core-image-build-and-release.md) for current acceptance status.

Browser locale behavior is authored in `web/static/ts/locale.ts` and compiled to the ignored `web/static/js/locale.js`. For direct `go-web` tests, first run `npm --prefix web ci --ignore-scripts --no-audit --no-fund` and `npm --prefix web run build` from the repository root; `make test` performs these steps. Web image builds compile the asset in a Node build stage; the runtime image does not include Node. The development overlay keeps that compiled asset from the image, so rebuild the image after changing the TypeScript source.
