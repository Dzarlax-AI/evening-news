Один Go/Cloak synthetic gate с остановленным memory-embeddings

17 октября 2026 · Редакция1 · Разрешение пользователя: «для того чтобы протестировать наш тест ... пригасим эмбеддинги на время тестирования». Подготовка до начала окна. Исполнение — после local checks и root review, без повторного запроса уже данного разрешения.

Цель и границы

На время одного runtime-only synthetic Go/Cloak gate остановить только существующий exact-ID контейнер memory-embeddings, затем вернуть тот же ID/image/config. Окно до10мин; семантический поиск Personal Memory временно может быть недоступен. news_web, memory-mcp, shared infra-chrome, PostgreSQL/Qdrant и остальные сервисы остаются работать. Не менять модели, env/config, volumes/data, scheduler, лимиты; не вызывать reindex/DB/AI/delivery и реальные publisher sites, не создавать PR/commit/push/images/deploy. Synthetic запрос непосредственно к восстановленному TEI для проверки вектора разрешён как health acceptance; ничего не сохраняется.

Текущее состояние и гипотеза

Предыдущий gate при остановленном News завершился на начальном host memory PSI0,90>0,50 ещё до test containers. В read-only интервале PSI отсутствовал. Embeddings занимал около586MiB RAM+1197MiB swap. Остановка embeddings — отдельный контрольный опыт; он не доказывает, что embeddings был источником прежнего PSI. Linux production amd64, локальный Mac ARM64. Использовать готовые проверенные Linux binaries без remote Go compilation.

Файлы и распределение работы

Luna1: scripts/run_go_cloak_linux_gate.py и tests/test_linux_vps_gate_harness.py — runtime-only --short-window с active6/hard8мин, независимо от профиля stopped-News; News/Chrome guards неизменны. Luna2: локальные ignored artifacts/embeddings-maintenance-gate-2026-10-17/embedding_controller.py и fake-tests на базе ранее проверенного контроллера. Root: review, свежий pinned payload/stage/TLS, точные операции на VPS, проверка возврата и cleanup, evidence. Общих файлов у executors нет; worktree не требуется, dirty work сохраняется.

Последовательность и обязательные guards

  1. До downtime: exact ID/image/StartedAt/restarts/OOM memory-embeddings; News/Chrome/Memory-MCP fingerprint+health, News home/feed; private TEI health/info и synthetic baseline vector shape; доступный cached APP/Cloak и bundle из54 Go/module inputs; disk≥7GiB, MemAvailable≥2432MiB, PSI≤0,50. Новый stage0700 и свежий synthetic TLS.
  2. До stop создать independent systemd timer embeddings-maintenance-return-<run>: on-active10min, accuracy1s, docker start exact embeddingsID; проверить active/waiting, точную команду и raw ActiveEnterTimestampMonotonic. Перед stop должно оставаться≥9мин. Если timer не подтверждён — stop запрещён.
  3. Docker stop exactID timeout20; exited/Pid0/exit0 или143/OOMfalse, прежние ID/image/restarts/StartedAt. Exit137/иной drift — немедленный start без gate. Измерить host и per-service PSI до/после stop и на abort; global PSI не трактовать как потребление Go.
  4. Один child --runtime-only --short-window с известным unique parent label. Максимум6мин активной работы/8мин общий hard deadline. Новые test containers/internal networks/own namespace rules; девять synthetic fixtures и relay overload/taint/cleanup. Никакого autoretry. Normal News/Chrome health/fingerprint/OOM и host PSI0,5/reserve1536/runtime working-set768/RSS128/disk guards не ослабляются. Контроллер проверяет embeddings действительно остаётся stopped; ранний возврат по timer прекращает опыт.

Обязательное восстановление

  1. При success/error/timeout/signal в finally убрать только свои exact-label test containers коротким bounded cleanup≤30с, чтобы не перекрывать загрузку модели с test browser. Даже при cleanup failure обязательно выполнить docker start exact embeddingsID; затем завершить остаточный scoped cleanup. Независимый10мин timer переживает SSH disconnect.
  2. Ограниченное ожидание running прежнего ID/image/restarts/OOM с ожидаемо новым StartedAt, private TEI /health200 и один synthetic /embed: numeric vector shape совпадает с baseline. Memory-MCP running и public /health200; root дополнительно проверяет доступность MCP инструментов без private-data retrieval. News/Chrome fingerprints неизменны, News health/home/feed успешны.
  3. Отключить backup timer только после recovery acceptance; named LoadState/ActiveState/SubState должны подтвердить inactive/dead, включая GC not-found. При неуспехе оставить backup armed, приоритет восстановлению и явный отчёт.
  4. Сохранить allowlisted evidence без env/tokens/private input, удалить только новый stage/helpers и свои ресурсы; не читать/переиспользовать старые private stages. Записать фактическое время окна. После результата обновить этот же документ.

Проверки и критерии результата

Local runner regression: short-window requires runtime-only, News-stopped profile конфликтует, default28/30 и normal News/Chrome guards сохранены. Controller fake tests: timer fail→нет stop; stopfailure/exit137→start; test failure/timeout→start; cleanup failure→start; recovery fail→timer остаётся; unitGC принят только inactive/dead; только exact embeddingsID получает stop/start. Root проверяет реальный code+tests и payload hashes. Native passed только при fixtures+overload acceptance, guard/fingerprint stability, scoped cleanup и восстановленном TEI synthetic path; иначе incomplete с точной причиной, без заявления об экономии RAM или установлении источника старого PSI.

Риски и статус

Загрузка модели после restart может вернуть холодные страницы в RAM и вызвать короткую нагрузку; лимиты сервиса и модель не меняются. Background Personal Memory запросы могут временно ошибаться; их вручную не инициировать. Safety guards могут снова остановить тест при PSI; новый повтор отдельно согласуется. Новые remote операции ещё не выполнены, сервисы работают.

Уточнение preflight до первого фактического gate

Первое окно stop/start в12:38UTC завершилось на post-stop preflight PSI0,90 при доступных3476,67MiB. Ни один child/test container не запускался. Embeddings восстановлен через11,2с, model/info/384D synthetic проверены, News/Chrome/Memory-MCP неизменны, backup снят.

Наблюдатель зарегистрировал переходные swap-in/major-fault/reclaim операции вокруг synthetic warmup и stop/start модели, PSI peak3,42. Это обосновывает ожидание стабильности до тестовой нагрузки; не является доказательством источника более старого пика.

В рамках исходного запроса выполнить тест с временно остановленными embeddings preflight исправляется до единственного фактического Go/Cloak gate: перед stop проверяются production reserve1536/PSI/health, поскольку candidate ещё отсутствует; после stop ждать максимум45с, проверяя unchanged production и stopped embeddings, пока три последовательных2с пробы не подтвердят admission2432 и PSI≤0,50. Breach reserve1536/health/OOM немедленно прекращает окно. При отсутствии стабилизации вернуть embeddings без child. Перед child вычислить hard timeout≤8мин и≤оставшийся timer budget−120с на cleanup/recovery. Фактический child будет запущен максимум один раз; после его failure/guard abort новых попыток нет. Source/runtime guards не ослаблены; обычный runner по-прежнему требует admission2432.

Предыдущее preflight evidence и executed controller сохраняются отдельно. Для первого фактического gate используется новый private stage/TLS и отдельный журнал; это ручное исправление порядка preflight, не автоматический цикл retry.

Фактический результат

Контрольный опыт выполнен; native acceptance incomplete. После preflight-only окна11,2с и bounded-settle исправления запущен один actual gate. Через37,2с он остановился waiting_chrome: общий cgroup working set781,125MiB>768, тестовый Cloak sampled peak754,68MiB. PSI0,00, доступно3213,64MiB; test worker/extraction/fixtures/overload ещё не стартовали. Это обнаруженный недостаточный бюджет synthetic стенда, а не исчерпание RAM VPS.

Embeddings возвращён за51,3с в actual gate окне; суммарно два stop-to-recovery окна62,5с. Root независимо проверил same ID/image/model, TEI health/info и384D synthetic vector, Memory-MCP health/get_stats, unchanged News/Chrome/Memory-MCP fingerprints/OOM/restarts, News home/feed. Exact-label resources, units, оба stage/helpers удалены. Пороги runtime guards не менялись; после actual gate failure повтора нет. Local runner142+7 subtests, controller15. Evidence: artifacts/embeddings-maintenance-gate-2026-10-17/result.json и README.md. Следующая работа — отдельная калибровка общего бюджета стенда перед дальнейшим remote gate; эти данные не доказывают экономию Go или завершённый native тест.
