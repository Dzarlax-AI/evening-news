17 октября 2026 · редакция 1 · Прототип остановлен после уточнения метрики; native runtime comparison не выполнен.

Цель и границы

Пользователь ответил «Ну вперед» на предложение собрать Go Linux-бинарники локально, выполнить изолированное сравнение Go + Cloak и Python + Cloak на одинаковых синтетических страницах на VPS, измерить память всего стека, CPU, время extraction и очистку. Это разрешение используется для локальной подготовки/test harness и одного условного последовательного B/C запуска после свежего успешного preflight.

Сравниваются B — существующий Python native-policy adapter и C — Go native service. Python-вариант использует production parser, но изменённый изолированный browser lifecycle/readiness; это не неизменённое приложение news_web. Результат не доказывает экономию полного production-приложения, AI/DB/pipeline или live-паритет.

Не входят production mutation/config/env/CDP/volumes, БД, AI, Telegram/Telegraph, сайты издателей, публичный DNS, старые private stages, Docker image builds/publication, commit/push/PR/deploy. Production health/home/feed допускаются только read-only.

Основание и необходимые изменения

scripts/benchmark_native_cloak.py уже поддерживает B/C, пять фиксированных fixtures, warmup, ordered cycles и native readiness. scripts/native_shadow_stand.py поддерживает B/C bootstrap runtime, но bounded gate разрешает только C; live mode запрещает bootstrap и делает внешний DNS lookup. Live mode не переиспользуется.

Нужен отдельный synthetic comparison mode с фиксированными corpus/origin и полным owned-cgroup allowlist. Go worker получает [data-ready="true"]; capabilities probe подтверждает selector и readiness. Legacy gate/live defaults не меняются. Измеритель учитывает relay, anchors, origin и observer/controller: суммируется один синхронный snapshot, отдельные максимумы компонентов не складываются.

Нагрузка и критерии

  • Один свежий private/internal stand для B, очистка, затем один свежий stand для C. В каждый момент работает только один вариант. Одинаковые pinned APP/Cloak и browser binary SHA; тот же TLS fixture/SPKI и корпус tests/fixtures/native-cloak/corpus.json.
  • По одному warmup на первом fixture; затем три последовательных цикла пяти cases: JS/cookie, redirect, slow, large DOM, challenge rejection. Максимум 16 extraction attempts на вариант, 32 всего; никакого повтора failed job. Ожидаемые content markers/state/error должны совпасть с corpus; непредусмотренный mismatch, native availability/ownership failure или timeout прекращает comparison без нового stand.
  • Concurrency 1, timeout одного job 30 s, одинаковые readiness: minimum navigation 500 ms, DOM stable 250 ms, network quiet 250 ms, ready selector. Warmup/cold-start показываются отдельно от измеряемых jobs.
  • Независимый от workload event loop синхронный sampler 200 ms: memory.current и anon/file/shmem по каждому owned-container; CPU usage/throttling deltas, PID и OOM counters. Sampling не должен останавливаться вместе с Python parser на том же asyncio loop. При недоступной telemetry — fail closed. Kernel memory.peak сохраняется при наличии; без него sampled peak явно подписан. Baseline, 5/30/60 s после workload; CPU/latency p50 и min/max, p95 с оговоркой малой выборки.
  • Полный stack sum включает app/observer, worker (C), Cloak, gateway, relay, три anchors и fixture origin. Отдельно показать controller/extractor + Cloak и общий fixture/test overhead; observer C не исчезает из total.
  • До/после jobs — read-only browser context/target count относительно baseline; рост, ошибка cleanup или отсутствие подтверждения прекращает сравнение. Raw socket namespace probes/traps проходят до workload обоих stand. Overload/taint gate — отдельная задача вне performance run.

Уточнение атрибуции памяти

Пользователь уточнил: Chrome общий для нескольких потребителей. Его полный cgroup расход нельзя приписывать Evening News или считать потенциальной экономией от Go. Последний read-only snapshot: news_web 159,56 MiB memory.current и 7,90 MiB swap; общий infra-chrome 450,27 MiB memory.current и 307,70 MiB swap. Это разовый снимок, не incremental extraction benchmark.

Python-приложение остаётся работать после выделения Go, поэтому отдельный Go worker сам по себе не удаляет текущий Python footprint. Полезная следующая метрика — память controller/extractor и приращение browser resources относительно idle на одинаковых synthetic jobs, с учётом остающегося Python web app. Общий shared Chrome не дублируется в attributable news total.

Новый сравнительный прототип не доведён до готовности; остановлен до remote stage/containers. Его текущий код и замечания сохранены отдельно в ignored evidence draft; active legacy scripts возвращены к их pre-task snapshot без потери прежних dirty changes. Runtime B/C comparison и production memory savings не подтверждены.

Результат и восстановление

Измерений runtime B/C нет. Артефакты подготовительных проверок: artifacts/runtime-comparison-2026-10-17/. При ошибке остановить только ресурсы с проверенной exact run label, сохранить ограниченное evidence, очистить новые synthetic credentials/stage. Откат локальных изменений по сохранённому diff без reset/stash всего рабочего дерева. Реальный запуск/успех фиксируется только по logs/metrics и independent postchecks.
