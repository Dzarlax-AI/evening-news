Implementation Plan: Bound Chrome Sessions and Add Low-Overhead Self-Healing

Status: implemented and locally verified; pull request preparation is in progress.

Prepared 21 August 2026 from origin/main at e60434e in an isolated worktree.

Task Summary

Prevent Evening News from silently hanging when the shared CloakBrowser/Chrome process degrades, without adding a second browser container or a permanent helper container. The selected design bounds every browser operation, disconnects the News CDP session after every processing cycle, suppresses retry storms, and gives the existing Chrome container a narrowly scoped self-restart path when recovery cannot be achieved at the client-session level.

Confirmed Current Behavior

  • The shared infra-chrome process reached 1,023 open file descriptors against its effective 1,024 limit.
  • At exhaustion, the health endpoint returned HTTP 502 and CloakBrowser repeatedly logged Too many open files.
  • Browser-backed source calls eventually stopped after their existing 120-second source budget, but article extraction later hung in an unbounded browser.get(..., new_tab=True).
  • The scheduler's outer 3,600-second timeout then killed the cycle and scheduled another attempt ten minutes later, producing repeated hour-long incidents and service-chat timeout alerts.
  • browser_pool.py retains one process-global remote connection until application shutdown. A successful processing cycle does not close it.
  • nodriver.Browser.aclose() in the deployed version closes the WebSocket and listener only; it does not terminate the remote Chromium process.
  • Previous production evidence showed that disconnecting/restarting only news_web reduced Chrome descriptors from 1,023 to 7, so releasing the News CDP client is an effective first recovery action.
  • After the authorised recovery restart, the next real processing cycle completed in 74.5 seconds and Chrome stabilised at 33 descriptors.

Selected Design

Keep one shared Chrome container. Treat the CDP connection as a per-processing-cycle resource, not an application-lifetime singleton. Escalate recovery in three bounded stages:

  1. Operation level: time out the stuck browser step and invalidate the current News session.
  2. Cycle level: always close the complete News CDP connection in a shielded finally block.
  3. Infrastructure level: after three consecutive browser failures, or before FD exhaustion, request one controlled restart of the shared Chrome container.

The application will not receive the Docker socket. A small shared control volume carries only a marker file. Chrome's existing healthcheck consumes the marker and terminates PID 1; the existing restart: always policy recreates the same pinned container. This grants News only the ability to request recovery of this browser, not arbitrary host/container control.

Desired Behavior

  • No browser command can keep a processing cycle blocked indefinitely.
  • A broken article or source is reported and skipped within a bounded budget; unrelated articles continue.
  • The News CDP WebSocket is closed after every processing cycle, including warning, failure, timeout, and cancellation paths.
  • A new cycle opens a fresh CDP session and does not reuse a socket left by a previous cycle.
  • One successful browser operation resets the consecutive browser-failure streak.
  • Three consecutive browser failures create at most one idempotent Chrome restart request.
  • The Chrome healthcheck restarts the container when the request is present, when its endpoint fails three times consecutively, or when descriptors cross a configurable pre-exhaustion threshold.
  • The existing shared browser consumer may see a brief interruption during the last-resort restart; the user has explicitly accepted this trade-off.
  • Operational Telegram alerts describe the first incident, the automatic recovery action, and final recovery without sending one message per article or retry.
  • No additional Chrome or watchdog container consumes steady-state memory.

Assumptions and Boundaries

  • The pinned production CloakBrowser image remains unchanged in this change.
  • Per-seed CloakBrowser processes and --idle-timeout are excluded because separate seeds create separate Chromium processes and would increase memory use.
  • The restart counter concerns browser/CDP failures only. AI, database, RSS, and Telegram failures must never restart Chrome.
  • The control volume contains no credentials, URLs, article content, or user data.
  • The descriptor threshold is configurable. Initial production rollout will use a conservative value below the observed 1,024 ceiling and validate it against normal post-cycle measurements before unattended operation.
  • No database migration is planned. Failure streak state is process-local; the idempotent marker and Chrome healthcheck provide the durable hand-off.
  • Infrastructure configuration under personal_ai_stack/deploy is a separate deployment artifact and will be changed and verified together with the application release, not silently during application tests.

Implementation Steps

  1. Add failing unit tests for a tab-open call that never returns, a navigation call that never returns, cancellation during connection startup, and cleanup after a failed cycle.
  2. Introduce one browser-operation timeout helper that logs operation type and exception class without logging sensitive page content.
  3. On browser timeout or transport failure, clear the global connection under the existing lock and await aclose() with the existing bounded cleanup timeout.
  4. Track consecutive browser failures centrally. Reset on confirmed browser success; write one marker atomically at the threshold and do not rewrite it until recovery is observed.
  5. Wrap the entire run_full_cycle() body in cleanup that closes the News CDP connection on success, warning, exception, cancellation, and outer scheduler timeout.
  6. Audit every browser_tab(), tab.get(), tab.send(), tab.evaluate(), and tab.get_content() path and apply the shared bounded helper rather than fixing only the observed extraction call.
  7. Change scheduler retry timing to bounded exponential delays and keep one active alert incident with a recovery message.
  8. Add the narrow control volume and healthcheck script. The script will validate only a marker file, endpoint response, failure counter, and descriptor count; it will never execute marker contents.
  9. Run focused tests, the complete Python test suite, and the same test command used by GitHub Actions before any push.
  10. Update this plan with actual values and evidence, then request separate permission for commit/PR and later for production deployment.

Test Plan

Automated application tests

  • Tab creation timeout returns a typed browser failure and closes the session.
  • Navigation, CDP command, evaluation, and content retrieval timeouts cannot escape their configured budgets.
  • tab.close() failure does not hide the primary extraction error.
  • Every cycle outcome awaits close_browser() exactly once.
  • Two failures do not request infrastructure recovery; the third writes one atomic marker.
  • A subsequent browser success resets the streak and allows a future independent incident.
  • Non-browser failures never touch the marker.
  • Scheduler retries back off and repeated alerts are suppressed while recovery produces one notification.
  • python -m pytest tests/ -q passes, matching the build-and-push workflow gate.

Infrastructure script checks

  • Healthy endpoint, normal descriptors, and no marker exit successfully without a signal.
  • One or two endpoint failures increment state but do not signal PID 1.
  • The third consecutive endpoint failure consumes state and signals PID 1.
  • A restart marker is treated as data only, consumed once, and cannot inject a command.
  • Descriptor count over the configured threshold signals PID 1 before the 1,024 ceiling.

Manual QA and Production Verification

  1. Record pre-deploy image digest, container health, restart counts, Chrome PID, FD count, active CDP targets, and recent scheduler state.
  2. Deploy only CI-built immutable application output and reviewed compose/script changes; preserve production .env, volumes, networks, and the pinned Chrome image.
  3. Run one real News processing cycle and verify structured success, article persistence, cycle duration, and a closed News CDP connection afterwards.
  4. Confirm Chrome remains healthy and its FD count returns close to the new post-cycle baseline instead of increasing monotonically.
  5. Inject a safe test marker, observe exactly one Chrome restart through Docker restart count, and verify the second shared consumer and News reconnect afterwards.
  6. Run another real processing cycle after the restart and verify the public News path and scheduler state, not only container health.
  7. Monitor at least several scheduled cycles for descriptor growth, timeout alerts, suppressed-repeat counts, and successful recovery notification.

Risks and Mitigations

RiskMitigation
Closing the News CDP session after every cycle adds reconnect overhead.One connection is created per cycle, while the remote Chromium process remains shared and warm; measure the real cycle delta during QA.
A restart interrupts the rare second browser consumer.Restart is last-resort and explicitly authorised; issue one operational alert and verify both consumers recover.
A malformed or hostile marker could execute code.The script tests only file existence and never reads or evaluates marker contents.
FD threshold is too low and causes unnecessary restarts.Make it configurable, compare it with recorded normal baselines, and start well above normal observed usage.
Cleanup cancellation leaves another stale socket.Run connection cleanup as a task protected with asyncio.shield() and await it before propagating cancellation.
More aggressive timeouts reduce extraction completeness.Keep existing adaptive page budgets, add only finite upper bounds, record failures as warnings, and validate against real browser-backed sources.

Rollback Plan

  1. Roll the News image back to the previously recorded immutable digest.
  2. Restore the prior News and infra compose files and remove the healthcheck script mount.
  3. Remove the unused control volume only after both compose stacks no longer reference it; it contains no persistent application data.
  4. Restart only the affected services, then verify Chrome health, News health, scheduler state, and one real processing path.
  5. If automatic recovery misbehaves, disable the marker path and FD threshold first while retaining the operation timeouts and per-cycle CDP cleanup.

Open Questions

  • The exact initial FD restart threshold will be selected from a fresh pre-deploy/post-cycle baseline; the observed hard ceiling is 1,024.
  • The exact navigation/content upper bounds will be reconciled with existing adaptive extraction budgets during implementation and captured here before deployment.
  • Upgrading CloakBrowser or adopting per-seed idle cleanup remains a separate future evaluation because it changes memory and compatibility characteristics.

  • Added finite, validated acquisition, tab creation, tab close, and CDP-operation deadlines.
  • Added hard-deadline handling for cancellation-resistant operations, typed transport failure handling, generation-scoped invalidation, and cancellation-safe cleanup.
  • Added cycle and tab leases so a finishing scheduled or manual cycle cannot close another caller's live session.
  • Wrapped browser navigation, CDP commands, evaluation, waits, and content retrieval in website, page-monitor, and Telegram extraction paths.

Known Limitations and Follow-up

  • No production deployment or live failure injection was performed during implementation.
  • The application changes are versioned in the Evening News pull request. The canonical personal_ai_stack deployment files are local operational artifacts and must be applied explicitly during the later deployment gate.
  • Real Chrome validation remains part of post-merge deployment QA: one normal cycle, one controlled marker restart, reconnection of both consumers, and several scheduled-cycle FD observations.
  • CloakBrowser upgrade and per-seed processes remain out of scope.
