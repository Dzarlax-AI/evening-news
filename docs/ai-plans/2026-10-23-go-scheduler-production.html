Standalone scheduler production cutover

Deployed and verified on October 23, 2026. PR #19 merged at 2b5ee16f1ec8f9b96d1f1b3f125f72ed5a2215f5 after review and successful CI. The daily DST correction is included. The first natural scheduled collection completed successfully; excluded services remained unchanged.

Scope and boundaries

Merge reviewed PR #19, publish the News application and standalone scheduler through CI, and deploy immutable digests. Move schedule ownership from the Python worker to the private Go scheduler. Keep Python execution, AI, delivery and recovery. Do not restart or change the collector, shared browser, egress gateway, Readeck, PostgreSQL or other services.

Observed baseline

News web and worker use app digest d9db70f4229619cc73dcce048ba8d81094fbefdad38140a314b8b95329f4e543, have zero restarts and no OOM. Shared PostgreSQL is version 17, with News role news_user, schema news, database aistack. Scheduler validation used PostgreSQL 16; verify provisioning and migration on 17 before cutover. Desired isolation

Use a separate scheduler database and non-superuser role on the existing PostgreSQL server. No News schema access. A private scheduler control network connects News web and scheduler. Both also retain the existing infrastructure network for PostgreSQL; the API listener is reachable there and requires its scoped bearer token on either network. No published port or public router. Credentials go in new private files with mode 0600; preserve the existing production .env. The worker receives the new dispatch mode but retains its existing execution lifecycle.

Release and cutover

  1. Review release workflow and deployment overlays on Luna, then independent review, commit/push to PR #19 and verify CI before merge.
  2. Publish Linux amd64 scheduler only through the explicit main-branch workflow after race, PostgreSQL and Docker fixture gates. Record commit, source hash, image digest and baseline container IDs.
  3. Provision isolated database/role and paused scheduler. Upgrade News application with Python scheduling initially retained; verify additive metadata migration and web/worker health.
  4. Disable only Python scheduling through a temporary overlay. Drain accepted work, verify no running schedules/jobs, then capture a private, bounded database snapshot of schedule/job metadata. Restore it into an isolated loopback snapshot database; run the existing bridge against that copy only.
  5. Import into paused Go scheduler, verify both keys, payloads, calendars and exact microsecond due times, plus role isolation. Switch web and worker to service mode. Verify authenticated facade, internal adapter and blocked public access.
  6. Resume Go only after the Python loop is confirmed stopped and the daily DST correction has passed review and acceptance. Observe an actual scheduled collection occurrence through durable acceptance to completed execution.

Checks and risks

Verify health/readiness, image provenance, pending/blocked occurrences, worker heartbeat, duplicate-free receipts/jobs and collection results. Measure memory/restart/OOM counters before and after; preserve browser/Readeck IDs and start times. Keep notifications on their existing scheduled paths; use synthetic or read-only checks for acceptance until the normal collection run.

The inherited daily fixed-offset DST bug can generate an extra digest near the autumn transition. The user approved correcting daily civil-time semantics before release. Do not silently change calendars or drop unsupported settings. A deployment health check alone does not prove the first scheduled run.

Rollback

Before activation, leave the existing Python owner active or restore its recorded image/configuration after a failed paused preparation. After activation, pause Go, wait out active dispatch leases, inventory accepted/pending/blocked occurrences and News receipts, and export current due times through the bridge. Reconcile accepted work before resuming Python. Never blindly restore old due times or delete scheduler state. Preserve additive metadata and receipt tables. Do not delete database volumes.
