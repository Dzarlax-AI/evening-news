Один synthetic gate при остановленном news_web

17 октября 2026 · редакция 1 · Согласовано пользователем «Давай» на явное предложение окна до 10 минут. Подготовка до начала простоя.

Разрешённое действие

Остановить только существующий контейнер news_web (Compose project news, service app) на время одного runtime-only synthetic Go/Cloak gate. Сайт и планировщик временно недоступны. Общий infra-chrome (project infra, service chrome) и остальные production services продолжают работать. Никаких compose up/pull, image changes, env/config/DB/AI/delivery действий, real publisher requests, PR/push/image publication/deploy. Штатный запуск news_web возвращает его прежнее приложение/планировщик.

Подготовка до downtime

  1. Сохранить dirty tree; Luna вносит scoped maintenance-mode изменения existing runner/tests. Обычный режим продолжает требовать работающий production. Root проверяет diff/tests.
  2. Свежие read-only fingerprint/health/home/feed, exact container IDs/images/StartedAt/restarts/OOM, общий Chrome healthy. Проверить systemd-run и transient timer facility. Новый private stage0700, свежие synthetic TLS cert/key; готовые локальные Linux binaries и 54 Go/module inputs проверяются по pinned bundle. Go toolchain/компиляция/race на VPS отсутствуют.
  3. Зафиксировать полный container ID news_web. До остановки создать независимый от SSH transient systemd timer: systemd-run --unit=news-maintenance-return-<run> --on-active=10min --timer-property=AccuracySec=1s --property=TimeoutStartSec=60s /usr/bin/docker start <exact_container_id>. Убедиться, что timer active/waiting и команда привязана к exact ID. Если timer не создан/не проверен — news_web не останавливать.

Один запуск и guards

  1. Остановить только exact ID news_web через docker stop --time 20 <ID>. Проверить exited/Pid0, exit0 либо143, OOMKilled=false, прежние ID/image/restart/StartedAt; unexpected exit137/изменение identity означает немедленный возврат сервиса без теста.
  2. Снять memory PSI/MemAvailable после остановки. Запустить --runtime-only --news-web-stopped --maintenance-container-id=<ID>. Разрешается только действительно остановленный expected news_web; если он неожиданно стартовал, gate прекращается. Общий Chrome должен сохранять running fingerprint/restarts/OOM.
  3. Admission2432 MiB, observed runtime budget768 MiB, reserve1536 MiB, PSI full avg10≤0,5%, host RSS128 MiB, disk/start/ownership/OOM/namespace guards остаются. Только health/memory news_web и home/feed checks временно заменяются strict expected-stopped-state проверкой. Никакого ослабления PSI ради прохождения.
  4. Активная работа максимум 6 минут, cleanup ещё2 минуты. Внутренний/независимый watchdog maintenance6/8 минут. Один свежий stand, девять synthetic fixtures, один relay overload и проверка taint/cleanup. Никакого autoretry после failure.

Остановка news_web — контрольный опыт. PSI общесистемный: остальные потребители остаются и повторный PSI stop возможен. Низкий working set сам по себе не устанавливает источник stalls.

Возврат независимо от результата

  1. В server-side try/finally после test/abort немедленно выполнить docker start <exact_ID>. Сервис возвращается также при ошибке cleanup; зависимость от SSH исключает backup timer.
  2. Подтвердить running/healthy news_web, прежний ID/image, expected changed StartedAt, unchanged OOM/restart baseline; общий Chrome unchanged. Проверить health, главную Evening News/news-list/feed-sentinel и public feed без DB-error mock.
  3. Только после подтверждённого восстановления остановить/удалить свои transient timer/service units. При таймере, сработавшем раньше, тест прекращается и данные отмечаются incomplete. Не удалять backup до running/healthy проверки. Если восстановление не подтверждено — приоритет восстановлению, остановить тестовые ресурсы и немедленно сообщить проблему.
  4. Удалить только exact-label test containers/networks и новый synthetic stage/helpers после сохранения allowlisted evidence; не читать/переиспользовать старые private stages. Root независимо проверяет user path, identity и cleanup. Записать фактическую длительность downtime.
