3. Diagnostic contracts

Heartbeat event

Retain existing finite stage/reason/SQLSTATE and phase durations. Capture worker generation and backend PID before lease invalidation, and emit them as structured fields with UTC timestamp and a stable event kind. Include available numeric runtime evidence such as goroutine count and recent GC pause metadata only if it is cheap and directly measured; do not infer a cause. Preserve errors.Is(err, ErrLeaseLost), immediate invalidation and cancellation ordering. Instrumentation must not query PostgreSQL, acquire a new connection, wait for collection, or postpone lease loss.

Example safe event: event=worker_heartbeat_failure generation=101 backend_pid=3201363 stage=commit reason=timeout commit_ms=4999. SQLSTATE is present only when validated; no raw error messages, DSNs or SQL.

Page Monitor event

Carry a request-scoped internal diagnostic context through source collection → Page Monitor → native Fetch. Source manager supplies numeric source_id from its descriptor and an opaque batch correlation token. Direct Page Monitor calls receive a server-generated token. Never log caller-controlled request IDs verbatim: correlate with a fixed-length SHA-256 fingerprint of the existing batch request ID, without changing the wire contract. Concurrent requests must never share mutable diagnostic state.

Emit at most one primary terminal failure event per Page Monitor operation, with correlation token, source_id when known, stage, finite reason, elapsed_ms and existing outcome/error_code. A separate bounded cleanup event may be recorded; cleanup must not overwrite the primary cause. Preserve typed causes through wrapping so busy, cancellation, deadline, ownership loss, event overflow and resource-limit classification remain unchanged.

Stages: admission, discovery, websocket, create_context, create_target, attach_target, configure, navigate, dom, cleanup. Reuse existing bounded reasons; add navigation_failed and evaluation_failed. Map navigation errorText into a small explicit allowlist of network categories (DNS, connection, TLS, aborted, other) before discarding the original. Unknown values become other; no arbitrary suffixes. Do not log URL/domain, source name, selectors, HTML, JavaScript, exceptionDetails, CDP payload, response content, raw error text or credentials. Keep public/persisted transport_failed and retry behavior unchanged.

4. Bounded operator incident collector

Add a standalone tool and runbook, with offline fixture/replay mode as default. Live mode requires an explicit operator invocation and a separately approved production observation window; it is not launched by this implementation or by the worker. No cron, daemon, new automation or persistent server files.

For a future approved observation, keep a small in-memory pre-event ring while following only structured heartbeat/source diagnostic events. Poll approved PostgreSQL metadata at most once per second through one separate operator connection, using read-only transactions and a 500 ms statement deadline; no added worker privileges or application pool usage. Bound live observation to 30 minutes with no automatic extension. A missed or late snapshot must be reported as missing evidence.

SQL allowlist: worker generation/backend PID/heartbeat age; pg_stat_activity PID, state, wait type/event, transaction age and blocker PIDs; numeric WAL/checkpoint counters. Exclude query text, bind values, client addresses and arbitrary application names. Resource allowlist: host memory/swap and PSI, container identity/start/restart/OOM, cgroup working set/cache, memory events and CPU throttling deltas. Read existing system metadata only; no browser/CDP calls, test jobs or website requests.

On an event, save bounded pre-event samples plus a current snapshot, event timestamp, collector timestamp and safe collection errors. Stop at 30 minutes or 5 MiB total local output, whichever comes first. Keep at most three incident bundles; stop instead of deleting an existing bundle. Never download full PostgreSQL/Docker logs, execute their contents or save unsanitized lines. A backend disappearing before a snapshot does not establish whether COMMIT was durable.

7. Risks, recovery and disk hygiene

Main risks are leaking diagnostic text, attributing concurrent errors to the wrong source, letting collection delay fencing, and mistaking a post-event snapshot for the original wait. Request-scoped metadata, finite serialization, no synchronous worker collector, pre-event samples and explicit missing-evidence flags address these risks.

No database migration or data rewrite is needed. Before merge, recovery is removal of this diagnostic patch. A future approved deployment can roll back the affected application/extractor image without restarting the shared browser or Readeck. Diagnostic events must never alter extraction output or ownership cleanup.

Reuse existing caches; do not create duplicate module caches, downloaded browsers or image archives. Fixture containers/volumes and task-owned temporary files must be cleaned in finally/trap paths, including failed checks. Keep only a compact sanitized result and the current bounded evidence. Do not prune unrelated Docker resources, user files or backups. Report remaining task artifacts and sizes.
