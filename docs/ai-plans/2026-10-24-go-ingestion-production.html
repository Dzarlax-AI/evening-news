  1. Проверить review/CI, release guard, merged revision и OCI revision/digests. Подготовить root-only recovery directory, baseline container fingerprints, compose/env hashes и News-only custom pg_dump; проверить dump listing.
  2. Подготовить candidate Compose без изменения защищённых services. Новый ingestion: private networks для DB/collector/executor, без ports/Traefik/browser mounts, 256 MiB, 0.5 CPU, 5 pooled DB connections + 1 lock. Новый отдельный login runtime role и non-login fence owner. Новые токены/env-файлы создаются только на сервере mode0600; существующие .env не перезаписываются.
  3. Поставить dispatch scheduler на pause через revision-protected control API, сохранить due instants/revisions и job rows. Дождаться drain, остановить только worker/executor. Не сбрасывать очередь и не менять расписания.
  4. Запустить новый web для normal additive migration012; проверить schema/function. Provision runtime role по проверенному SQL после migration. Запустить ingestion, проверить health/auth/private routing и узкие DB privileges. Запустить новый executor и прежний Go worker; дождаться healthy/lease.
  5. Восстановить исходное состояние dispatch. Проверить один обычный configured-source collection job (естественный плановый приоритетно, либо один durable processing job в рамках разрешённой приёмки); не делать отдельные probes к новым реальным сайтам и не запускать дополнительный digest.
  6. Проверить run/source receipts, counters, cursor/hash, новые статьи, errors/busy/exhausted, публичные health/feed, private endpoint auth. Снять память/PSI/restart/OOM snapshots до/после, сравнить fingerprints browser/Readeck/collector/scheduler/PG/egress и исходные env hashes. Зафиксировать actual results и release record.

Риски и откат

Риски: grants/schema drift, private network reachability, stale lease и late writes при смене executor, recoverable collection partials, расход памяти. Использовать только explicit service targets --no-deps при recreation. Не выполнять общий compose up/down, не менять nft/browser/readeck и не перезапускать PostgreSQL. При ошибке сохранить диагностику; решение об откате отдельно согласуется по deploy-personal. Технический откат: pause/drain, stop ingestion/executor, вернуть saved compose/старые app digest и Python collection mode, запустить прежний worker; additive tables и новые данные оставить. Backup не восстанавливать поверх новых статей, volumes не удалять.
