Один рабочий env и очистка хвостов

Редакция 1 · 26 октября 2026 · одобрен пользователем («Го»), реализация на Луне начата. Запрос: «Почисти хвосты и слей все env в один файл».

Результат

У News один рабочий /root/news/.env с правами0600 и обычный Compose. Ни дополнительных config services, ни новых контейнеров или обёрток запуска. Compose явно передаёт каждой роли её параметры; полный файл со всеми секретами не подключается как общий env_file ко всем контейнерам. Исчезают ссылки активной конфигурации на env-файлы прошлых релизов. Убираются только доказанные ненужные runtime-зависимости и устаревшие сведения README.

AI, договоры API, схема БД, роли/права PostgreSQL, расписания, токены и их значения, concurrency и лимиты не меняются. Browser/Readeck/PG/Traefik не изменять и не перезапускать. Extractor/egress не пересоздавать: их env mappings можно нормализовать при доказанном полном совпадении effective values. Новых компонентов и миграции логики на Go в этом этапе нет.

Один файл без смешивания прав

  1. Собрать на VPS snapshot фактически действующих параметров, сохранив порядок старых overrides. Секреты остаются на VPS, в Git/Mac/логи не выводятся. Новое содержимое строится из production baseline, а не из локального .env.
  2. Один .env группируется комментариями по обязанностям. Конфликтующие DSN получают явные имена WEB_DATABASE_URL и EXECUTOR_DATABASE_URL; background сохраняет WORKER/INGESTION/PROCESSING/SCHEDULER_DATABASE_URL. Внутри web/executor переменная по-прежнему называется DATABASE_URL через явный Compose mapping. Существующие границы токенов и отдельные DSN не объединяются.
  3. Дедуплицировать общие settings только при совпадении значения и смысла. Например, client/server названия одного credential можно связать с одним ключом .env, но разные DB-роли никогда не сливаются. Каждая роль получает прежний набор ключей, provider secrets не попадают в web/background.
  4. Проверить dotenv-экранирование через installed Compose: доллары, кавычки, обратные слеши, JSON/списки, пробелы, пустые и многострочные значения. Сравнение before/after effective environments всех5ролей побайтное; отчёт содержит только имена несовпавших ключей и counts. Никаких значений или credential hashes наружу.
  5. Атомарно установить согласованные .env+Compose, не запуская общий compose up. Не перезапускать роли ради смены источника идентичных значений. Новая terminal command использует штатный Compose в /root/news, без обязательной зависимости от shell-exported секретов; проверить отсутствие env overrides текущего shell.
  6. После приёмки убрать старые News-owned env-файлы из активного дерева только с подтверждённым отсутствием внешних потребителей. Их прежние байты и Compose сохраняются в одном root-only rollback-архиве, проверенном перед удалением оригиналов. Чужие файлы, данные, volumes, старые images и остальной release evidence не удалять. При неясном потребителе конкретный файл не удаляется, ограничение сообщается; активный News всё равно читает один .env.

Проверки и применение

  1. Локально: synthetic round-trip .env→Compose, precedence и fail-closed missing settings; равенство role environments и отсутствие credential leakage между ролями. В fixtures только искусственные секреты. Проверить чистый install нового executor, CLI help без сети, migration imports, backup/media callbacks, Python suite и consolidated71-check gate. Docker disk preflight; без массового prune. CI подтверждает Linux/amd64, ARM64 локально при доступном месте. Не обещать image savings без измерения.
  2. PR и независимый review фактического diff; если CI/review зелёные — merge и штатный reviewed-main core publication. Pipeline выпускает три принятых core targets без новых repositories; при cleanup только executor в production меняет digest, web/background сохраняют принятые версии. Если dependencies не меняются, новый release images не нужен.
  3. Config-only перенос одного env выполняется без рестартов при полном равенстве effective values. Для нового executor image — штатный pause/drain, замена только executor на опубликованный digest, private/public smoke и resume с сохранением schedule revisions/due instants. Не пересоздавать browser, Readeck, extractor, egress, PG или Traefik.
  4. Принять первый обычный плановый8-source проход: jobs/Go receipts, busy, новые exhausted/rejected, heartbeat/generation, working set/cache/PSI/swap, restart/OOM и protected fingerprints. Без forced collection/real-site тестов, переобработки, тестового digest или внешних сообщений.
  5. Обновить этот план actual results и память проекта. Проверить сохранность посторонних пользовательских файлов. Старую причину heartbeat timeout явно оставить неизвестной, если read-only evidence её не установит.

Риски, возврат и одобрение

Главные риски — потерять override/escaping, склеить разные DB-роли, отдать всем контейнерам все секреты, удалить внешний источник env или убрать библиотеку со скрытым потребителем. До применения нужна проверка идентичности значений, безопасного распространения ключей и чистого executor. Два файла .env/Compose меняются как согласованная пара; при отсутствии возможности безопасной установки перенос останавливается до решения.

Для возврата сохранены прежние Compose/env bytes и текущий executor digest. Автоматического rollback нет; восстановление и рестарты только после решения пользователя. Схему БД и данные не откатывать.

Запрашиваемое одобрение: этот bounded cleanup на Луне; commit/push, один PR/review и merge при зелёных checks; production перенос News на один .env с прежними значениями и чистка подтверждённых старых env с одним rollback-архивом. Если меняются dependencies — публикация штатных core images и замена только executor после gates, с pause/drain/resume и обычным плановым проходом. Browser/Readeck и защищённые соседи остаются вне изменений. Пользователь одобрил план ответом «Го». Разрешены перечисленные реализация, PR/review, merge и ограниченное применение; прочие границы сохранены.
