Сбор Telegram-каналов на Go

22 октября 2026 · Редакция 1 · Approved / Implemented locally. Пользователь одобрил эту редакцию: «Го, делай по плану на Луне, потом PR и review». Контекст: Go article extractor уже выкачен; пользователь поручил перейти к Telegram. Реализацию выполняет Luna, интеграцию и приёмку — основной агент.

Цель и граница этапа

Подготовить Go-парсер целой страницы публичного Telegram-канала, совместимый с текущими Python Article. На первом этапе работаем только с локальными HTML fixtures: получаем список постов и подтверждаем паритет. Новый сервис, API endpoint, контейнер, scheduler, БД или browser pool не создаём. Рабочую Telegram-доставку и Telegraph не меняем, тестовые сообщения не отправляем. Production и Readeck остаются в текущем состоянии.

После принятого парсера следующий небольшой этап — подключение получения страницы и Python caller к существующему Go-сервису. Его сетевой контракт будет показан отдельно; данный план не разрешает молча расширить одиночный article API до batch source API.

Что подтверждено кодом

  • news_aggregator/telegram/telegram_source.py: Python сначала использует shared browser с ожиданием и тремя прокрутками, затем HTTP. _parse_html возвращает список Article.
  • message_parser.py сохраняет дату, ID, пересылку и медиа до удаления Telegram UI; для короткого сообщения может отдельно загрузить внешнюю статью. В офлайн-сравнении эта сеть заменяется явной заглушкой, текст поста сохраняется.
  • go/extractor/sources.go: extractTelegram уже разбирает один пост по EntryIndex. telegram_media.go содержит media helpers. Однако текущий одиночный Result не равен списку Python Article с raw_data.
  • URL Python Article может быть внешней статьёй; Telegram URL и message_id всё равно нужны отдельно. Подмена всех URL на t.me нарушит существующую идентичность.

Внутренний контракт и совместимость

Новая локальная функция ParseTelegramChannel в пакете extractor принимает HTML, URL страницы, имя/идентификатор источника, положительный лимит постов и фиксированное время для fallback отсутствующей даты. Возвращает упорядоченный список постов и явный результат ошибки лимита/входа. Это внутренний Go-контракт, пока без HTTP serialization API.

Каждый пост сохраняет title, url, content, published_at, image_url, media_files, source_type/source_name и существующие raw_data: channel, access_method, content_length, media_info, has_media, media_count, external_links, hashtags, original_link, forwarded_from, message_id, telegram_url. Альбомы, подписи, относительные ссылки, Unicode, media-only и forwarded/reply посты проверяются отдельно. Channel avatar и video preview не становятся отдельными картинками поста.

DOM разбирается один раз, лимит останавливает дальнейший разбор постов. Существующие byte/text bounds переиспользуются. Успешные посты не исчезают из-за одного некорректного сообщения; ошибка всей страницы и пустой результат различаются. Существующий extractTelegram/replay и article API сохраняют совместимость. Отдельная загрузка внешних статей остаётся за границей чистого парсера.

Файлы и последовательность

  1. Собрать синтетические HTML fixtures и нормализованный Python baseline из MessageParser. Заглушить external enrichment. Единственное выявленное runtime-dependent различие: Python hash() в сгенерированных fragment-ID poll/contact/location меняется между процессами. В сравнении нормализовать только этот суффикс, проверяя тип и полный payload; реальные URL, Telegram identity и message_id сравнивать точно. Go использует стабильные fragment-ID. Фиксированное время задаётся явно.
  2. Luna реализует новый go/extractor/telegram_source.go и scoped tests; переиспользует существующие Telegram helpers. Изменения sources.go/telegram_media.go допустимы только для совместного использования логики с сохранением старых результатов.
  3. Сравнить Go/Python по тексту, идентичности, датам и каждому виду метаданных; выявленные расхождения исправить либо показать для согласования. Новые fixtures предполагаются в tests/fixtures/telegram/, Python baseline tests — в новом tests/test_telegram_source_parity.py.
  4. Независимый reviewer проверяет реальный diff, ограничения, паритет и отсутствие сетевых вызовов. После принятия — PR с review, как оговорено для проекта. Рабочий маршрут пока не переключается.

Задачи идут последовательно: baseline → реализация Luna → независимый review → совместная приёмка. Параллельное редактирование общих parser helpers не требуется.

Проверки и критерии приёмки

  • Фикстуры: текст, внешний URL, forwarding/reply/UI cleanup, даты с timezone и без даты, фото/альбом, video/poster, audio/document, остальные поддерживаемые media types, media-only, короткий пустой пост, malformed HTML, лимиты, сохранение порядка. Все посты и metadata сравниваются с Python baseline.
  • Планируется: scoped Python parity tests; cd go && go test ./extractor -count=1 и go test -race ./extractor. Повторный parse даёт стабильные ID/URL; неизвестное или пропущенное поле не объявляется паритетом.
  • Уже выполнено при подготовке: go test ./extractor -run Telegram -count=1 — PASS; три существующих Python parse tests — PASS. Это текущий baseline, не доказательство новой реализации.
  • На данном этапе не запускались реальные Telegram fetch, production mutation, AI, DB writes и Telegram/Telegraph send. Live acceptance будущего подключения будет чтением каналов без отправки сообщений.

Риски, rollback и решение

Основные риски: потеря метаданных при переиспользовании одиночного Result, изменение whitespace/заголовков, подмена Telegram identity внешним URL, сетевое обогащение внутри fixture tests и повторный разбор полного DOM на каждый пост. Приёмка должна обнаружить эти различия до рабочего подключения. Изменения полностью локальны; rollback — отказаться от нового parser adapter, существующий Python продолжает работать. Ничего из текущих локальных изменений не сбрасывается.

Одобрен именно этот этап: чистый Go-парсер списка постов, fixtures/parity и PR/review. Полный перенос доставки, scheduler, схемы БД и production-переключение Telegram в него не входят.

Результат реализации и проверки

Luna реализовала только новый офлайн-парсер и fixtures. Существующие Python production source, Go single-article extractor, HTTP API, контейнеры и конфиги не изменены. Добавлены go/extractor/telegram_source.go, scoped Go tests, tests/test_telegram_source_parity.py, четыре HTML case и Python-generated JSON baseline. Контракт описан в docs/go-telegram-source.md.

Baseline содержит 29 принятых постов в пяти случаях; Python проверяет его действующим парсером с замороженными часами и заглушкой external enrichment, Go независимо проверяет те же данные. При сравнении дополнительно нормализуется только представление UTC дробных секунд с сохранением микросекундной точности Python; реальные URL и ID остаются точными. Независимая root-проверка 13 дополнительных synthetic случаев прошла, включая Unicode, tracking/query identity, большие ID, вложенную пересылку, дробные даты и раздельные длительности двух audio/video.

При review исправлены фактические расхождения: forwarded whitespace и кириллические @mentions, порядок CSS background photos после direct media, media-only документ без preview, очистка controls/forwarded text. Дополнительно проверено имя канала со смешанным регистром: channel приводится к нижнему регистру как в Python, реальные permalink и access_method сохраняются. Production fetch не изменялся. Локальная проверка публичного https://t.me/s/Serbia 22 октября: один HTTP capture, 145122 байта, 14 постов. Первое сравнение выявило потерю query при точке с запятой; исправление и обезличенный synthetic regression добавлены. Повторное сравнение всех 14 постов с действующим Python parser прошло без расхождений, включая ссылки, даты и media metadata. Внешнее enrichment отключено; БД, AI и рассылки не использовались. Проверка выполнена после создания PR, что было пропуском в порядке приёмки; универсальный паритет других каналов не заявляется. Свежая root-проверка: 7 Python tests PASS, go test -race -count=1 ./extractor PASS, go vet ./extractor PASS, git diff --check PASS. PR #11 прошёл первый Linux CI. Минимальная схема и контракт

Новый приватный POST /v1/telegram/fetch в существующем Go extractor, с тем же Bearer token, admission slots, drain/cancellation и лимитами. Новый request: contract_version, request_id, channel_url, source_name, положительный limit до 100, budget_ms до существующих 30 секунд. Нет HTML injection, произвольных browser selectors или настроек сети в production request. Channel URL канонизируется в HTTPS t.me/s/username; допустимы только известные Telegram host/path, без credentials, нестандартных ports и произвольных query. Все redirect, DNS и dial проходят существующие public URL guards.

Go сначала получает публичный preview HTTP; при пригодном HTML сразу разбирает его. Только при допустимой неудаче HTTP/отсутствии постов выполняется один native Cloak fallback с фиксированным Telegram selector. Policy/auth/resource-limit/429 не запускают слепые повторы. Общий browser/context lifecycle и memory limits сохраняются, новый браузер не создаётся. Возвращается versioned envelope: request_id, original_url, final_url, outcome success/partial/failed/rejected, articles, error с конечным code/retryable. Max page 5 MiB, max post 100000 символов; общий JSON ограничен совместимым клиентским пределом 5 MiB. Oversize metadata/media проверяются до сериализации; нельзя молча обрезать идентичность/контент.

При partial успешный префикс сохраняется, caller явно фиксирует частичный результат без исключения после yield: текущий SourceManager на исключении теряет уже собранные статьи. Непринятые посты не помечаются обработанными; следующий обычный fetch остаётся возможным. Пустая/ошибочная страница отличается от успешной. Deadline, busy, cancellation и resource_limit различаются.

Python и совместимость

Новый TELEGRAM_SOURCE_MODE=python|go, default python, независимо от article extractor mode. При go Python только вызывает endpoint и переводит проверенные поля в существующий Article; без Python browser/parser fallback. Сохраняются Telegram identity, внешний URL, timezone, media/raw_data и порядок. Существующее обогащение короткого поста (менее 200 символов, внешний оригинал, замена только при тексте более чем вдвое длиннее) выполняется через существующий Go article API; ошибка обогащения сохраняет исходный пост. Последовательно и в существующем общем source budget, без неограниченной сети или параллелизма. После замены обновляются title/hashtags/content_length по существующим правилам. Delivery, Telegraph, AI, DB schema и scheduler не переписываются.

Риски и восстановление

Основные риски: полнота HTTP preview относительно browser scroll, JSON amplification, перерасход source budget на enrichment, partial-result loss, несовместимость app/worker версий. Противодействие: сравнение реально включённого канала, synthetic browser path, общий bounded lifecycle, adapter validation и явный partial. Если HTTP даёт меньше новостей, чем рабочий browser, переключение не принимается до выяснения. Восстановление — вернуть предыдущие pinned app/worker digests и TELEGRAM_SOURCE_MODE=python из receipt, без сброса данных и local work. При failed startup сначала диагностика и решение с пользователем; автоматический rollback не предполагается.

На старте редакции 2 были проверены исходный parser/live capture, зелёный CI и read-only доступ/здоровье News. Текущий прогресс: Luna реализовала endpoint и adapter; root выполнил полный Go race/vet/mod verify PASS и реальные loopback endpoint/client/TelegramSource проверки: свежая страница содержит 7 контейнеров, Python и Go принимают все 7, media count 18; Python fetch/parser fallback запрещены тестом, enrichment заглушен. Старый capture сохраняет 14/14 паритет. Финальная локальная проверка: 948 Python tests PASS, 8 skipped, 22 subtests; все Go race tests, vet и module verify PASS. Добавлены проверки amplified response, partial prefix, alias redirects, media fallback parity, deadline reserve и конечного event_overflow. CI нового head, isolated Linux campaign и production rollout ещё ожидаются. Открыто: новые замечания review parser закрываются до принятия. Одобрение редакции 2 включает описанную реализацию на Луне и ограниченный News rollout после перечисленных проверок; общая browser инфраструктура, Readeck и Assistant вне изменений.
