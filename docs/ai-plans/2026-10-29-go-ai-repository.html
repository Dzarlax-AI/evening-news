2. Граница библиотеки

Переносим существующий контракт и поведение без расширения API: одна HTTP-попытка, отмена через context, ограниченные размеры данных, структурированный JSON, безопасные ошибки, статусы complete/refusal/incomplete, известные и неизвестные значения usage. Сохраняем особенности схем и учёта токенов обоих провайдеров. Package name остаётся ai; меняется только module/import path.

В News остаются промпты, редакционные проверки, ссылки, настройки установки, ключи из env, сохранение данных, цены, лимитер, повторы, breaker и Telegram. В библиотеке нет News-типов, загрузки env, БД, контейнера или сервера. Health и Assistant пока только потенциальные потребители: их код и конфигурацию не читаем и не меняем в рамках этого этапа.

Не добавляем новых провайдеров, streaming, embeddings, function calling, автоматический fallback или другие модели. Русский дайджест и будущая сербская локализация сохраняют прежние границы.

Целевой репозиторий — Dzarlax-AI/go-ai, один Go-модуль в корне. Пользователь подтвердил публичный доступ и лицензию MIT. News сможет получать модуль без дополнительных credentials. Первая версия — v0.1.0 на проверенном коммите. Дальнейшие релизы — явные теги SemVer; выпущенные теги не перемещаем и не переписываем. До v1 изменения API документируются в CHANGELOG; News обновляет версию только отдельным проверяемым изменением. Зависимость не указывает на main, latest или локальную директорию.

Новый репозиторий получает только текущие исходники библиотеки и её тесты, а не историю, артефакты, секреты или документы всего News. Исходный News-коммит записываем в CHANGELOG первого релиза. README содержит компилируемые примеры text и structured JSON без настоящих ключей.

7. Риски, откат и уборка

Главный риск — недоступная версия в CI/Docker: News PR нельзя считать готовым до успешного скачивания опубликованного тега без sibling checkout. Для выбранного публичного репозитория оставляем штатную проверку checksum, не отключаем GOSUMDB.

Второй риск — выпадение CI при удалении job/path filters: проверить needs и фактический запуск всех интеграционных gates. Третий — скрытое изменение поведения при переносе: сохранить существующие тесты и отдельно сравнить diff к исходному go-ai из #45.

До merge News откат — закрыть/исправить PR; работающая установка не меняется. После разрешённого merge возможен отдельный revert News на прежнюю реализацию из #45; released тег библиотеки не удалять и не перемещать, исправления выпускать новой версией. Production rollback и деплой не входят в этап.

Удалять только созданные этим этапом временные consumer, cache, fixtures, тестовые процессы и сборочные файлы после проверок. Не удалять общий пользовательский Go/Docker cache, чужие контейнеры, старые бэкапы или несвязанные файлы. Оставить компактные логи и версии проверенных коммитов; не создавать объёмные копии репозиториев для архива.
