Что подтверждено на сервере

После PR49 private domain и background работают на 0230dd1c93af1ff869de72e756a1d0bd2453161b; восстановленный дайджест доставлен. Канонический Compose использует существующие Cloak/CDP, egress, две вкладки и сети infra, news-browser-control, news-job-control, news-scheduler-control, news-extractor-outbound и traefik. HTTPS origin и доверенные proxy CIDR заданы. На сервере нет managed-таблиц. Схемой news и 120 её relations владеет news_user; web, domain и worker используют эту же роль. Execution, ingestion, processing и scheduler уже используют отдельные ограниченные роли.

В legacy domain окружении остались параметры удалённого Python runtime; background задаёт GOMAXPROCS и GOMEMLIMIT. Установщик обязан отказать неизвестным ключам и owner-runtime, а не обходить свои проверки.

Совместимость в том же PR48

На Luna объединить PR49 с PR48, сохранив готовые саммари, классификацию ошибок и managed operational snapshots. Явно исключить только доказанно неиспользуемые legacy domain-параметры; неизвестные параметры продолжать отклонять. Два стандартных параметра Go runtime перенести без изменения в process environment generated override: Go читает их до загрузки прикладного manifest. Тесты должны подтвердить отсутствие утечки прикладных env и секретов.

Необходимая дельта утверждённого плана

В исходном плане сказано: «Ни массовой ротации токенов, ни новых DB-пользователей на месте существующих». Сохранить runtime news_user нельзя: установщик запрещает роль-владельца, а общий owner не разделяет web, domain и worker. Предлагается заменить только три runtime identity:

КомпонентНовая рольДоступ
Webnews_web_runtimeПубличное чтение, admin CRUD, очередь, managed auth; без integration_credentials.
Private domainnews_domain_runtimeAI, редакционные выпуски, delivery receipts и encrypted credentials; без захвата worker lease и auth-таблиц.
Workernews_worker_runtimeТолько необходимые чтение/обновление очереди, worker heartbeat и execution receipts; без auth/credentials.

Новые роли LOGIN NOINHERIT NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS; случайные пароли генерируются оператором в приватном состоянии, не в argv/log. Права берутся из проверенной таблицы go-tools/managedsetup/grants.sql и ограничиваются названными ролями/объектами News. Никакого ALTER OWNER, DROP/REVOKE старой news_user, смены владельцев 120 relations или REVOKE PUBLIC в shared database. news_user остаётся владельцем и одноразовым bootstrap для аддитивной 016. Existing execution/ingestion/processing/scheduler identities не ротируются.

У трёх DSN меняются только identity/password; host, port, database, search_path и данные остаются на месте. Это отдельное разрешение, а не молчаливое изменение утверждённого preservation-контракта. Роли и данные соседей не меняются.

Порядок выката после разрешения

  1. Завершить один PR48, независимое review и CI точного нового head; merge, штатная публикация трёх core images и extractor image. Проверить digest и OCI revision. Не включать новый браузер в Compose.
  2. Сохранить один компактный rollback bundle с прежним Compose/immutable pins и приватной конфигурацией; сделать проверенный backup только схемы News. Не создавать полную копию shared PostgreSQL. Секреты хранятся root-only.
  3. CAS pause dispatch News, дождаться пустых активных очередей и outbox; сохранить расписания, due instants, receipts, worker/neighbor fingerprints. Остановить только app, executor, background, extractor и egress. Shared browser, Readeck, PostgreSQL и proxy не останавливать.
  4. Создать только три ограниченные роли и scope grants, выполнить additive migration016 и проверки. Сформировать защищённый canonical Compose с новыми тремя identities и точными image pins. Выполнить adopt --dry-run и затем apply; importer не создаёт роли и не расширяет privileges сам. При ошибке не продолжать автоматически.
  5. Импортировать администратора, прежний signing key, provider/Telegram credentials, runtime token links и operational settings; не делать AI/send/test вызовы при импорте. Сохранить данные и расписания; проверить deny-доступ к секретным таблицам у web/background и невозможность runtime DDL/owner.
  6. Запустить те же пять News runtimes с generated role files и прежними сетями/ресурсами. Сверить неизменность CDP/egress/tokens, двух вкладок, endpoints и protected fingerprints. Возобновить прежнее состояние dispatch без изменения расписаний.
  7. Проверить прежний admin login/cookie, write-only credential settings, публичный дайджест и статью, нормальный плановый проход с 8 источниками, heartbeat/receipts, memory/PSI/OOM/restarts. Не отправлять повторный дайджест автоматически.

Восстановление и ограничения

Универсальный newsctl recovery не поддерживает adopted/native профиль. Операторское восстановление: остановить только пять News runtimes, вернуть исходный canonical Compose/его immutable pins и прежние runtime identity, запустить эти же сервисы; аддитивные managed-таблицы не удалять и не перезаписывать статьи/receipts. Не применять автоматически. При необходимости восстанавливать encrypted credentials нужны сохранённые managed private key/state, одного dump недостаточно. До acceptance не менять через UI ключи/пароль и не удалять старую приватную конфигурацию. Полностью удалить старые env и rollback material можно только после отдельного решения. После проверок убрать task-owned fixtures, файлы и caches; оставить компактное evidence и единственный необходимый rollback bundle.

Gate

Запрос «Катим?» разрешает подготовку и согласованный выкат PR48. Он не отменяет явно обещанное сохранение DB identities. До отдельного одобрения трёх ограниченных runtime-ролей production остаётся неизменным. Обоснование gate — live owner metadata и прямое правило preflightAdoptionRoles, не гипотетическое опасение.

Обсуждение числа ролей

Владелец уточнил необходимость семи ролей; это не одобрение их создания. Число семь не является требованием производительности: оно отражает существующие границы SQL-полномочий. Возможна отдельная консолидация прав фоновых компонентов, но текущий выкат её не включает. Рекомендация текущего перехода — сохранить четыре существующие ограниченные роли и заменить общую owner identity тремя runtime-ролями; решение остаётся за владельцем.
