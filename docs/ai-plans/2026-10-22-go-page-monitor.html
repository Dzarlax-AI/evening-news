Цель и границы

Перенести получение страницы, управление Cloak-контекстом и извлечение списка публикаций в уже работающий Go extractor. Сохранить настройки источников, обнаружение новых публикаций, обучение селекторам и существующее сохранение статей. Измерить скорость и потребление ресурсов до и после; заранее обещать коэффициент ускорения оснований нет.

Один существующий Go-сервис и один общий production CloakBrowser. Новые контейнеры, базы и инфраструктурные компоненты для рабочего решения не нужны. Python сохраняет оркестрацию, загрузку/сохранение обученных селекторов, вызовы AI и небольшое состояние мониторинга. RSS, Telegram, рассылка, AI-модели, схема БД и общие browser/firewall настройки вне изменений. Readeck продолжает работать; Assistant остаётся остановлен.

Решение и внутренний контракт

Новый приватный POST /v1/page-monitor/extract в том же service handler. Две строго различимые операции: fetch получает страницу и разбирает список; parse разбирает уже полученный HTML после обучения селекторам и не выполняет сетевых запросов. Это позволяет сохранить AI learning с одним получением страницы и без серверного кэша HTML или новых browser sessions.

Запрос: версия контракта, request_id, URL/имя источника, операция, configured/learned селекторы с приоритетами, use_browser, wait_for_js, minimum title length, item limit и общий budget. HTML и время исходного snapshot разрешены только для parse. Нет произвольного JavaScript, browser endpoint, proxy/network настроек или caller-controlled permissions. Python передаёт действующие настройки, без скрытого перевода browser-источников на HTTP.

Ответ: версия/build/request identity, исходный и конечный URL, исход операции, fetch method, упорядоченные items, snapshot timestamp/content hash, применённые селекторы и конечный код ошибки. Items сохраняют title/link/description/date/content type и идентичность исходного монитора. При сигнале list-page fallback возвращается bounded HTML для существующего Python AI analyzer; затем допускается один parse того же HTML с новыми селекторами. AI и persistence не вызываются внутри Go.

Пределы используют существующие transport/service значения: HTML до 5 MiB, JSON request/response до 8 MiB, fetch/parse budget до 30 секунд, item limit 1–100 по настройке с default 20, ответ от нуля до этого лимита. До 64 селекторов в каждой из четырёх групп, каждый до 2048 bytes; дополнительные группы приоритета также учитываются в общем пределе 256 строк. Превышение не скрывается: resource_limit/partial с ограниченным успешным префиксом. JSON escaping учитывается до большой сериализации. Неподдерживаемый CSS не превращается в успешный пустой список: явная диагностика без исполнения JS.

Новые операции используют существующие auth, общий semaphore, cancellation, drain и stats. Fetch применяет текущие public URL/DNS/dial/redirect ограничения, native egress и owned-context cleanup. Parse не получает сетевого доступа. resource_limit, event_overflow, unavailable, auth/policy errors и обычная пустая страница различаются; лимиты не запускают повторное обучение или неограниченный retry.

Совместимость и состояние

  • Сначала фиксируются Python fixtures с frozen clock: learned/configured selector order, duplicate titles, parent/self links, relative URLs, Unicode, описание 500 символов, относительные/невалидные/отсутствующие даты и список, ошибочно распознанный как одна статья. Go list parser создаёт DOM один раз; существующий single-article custom extractor сохраняет старые результаты.
  • Python сохраняет существующее вычисление article hashes, last_snapshot и failure counters. Ошибка получения/контракта не заменяет последний успешный snapshot; resource-limit не считается поводом для AI learning. Временные метки на границе с ORM — naive UTC. Первый, повторный, изменённый и пустой успешный snapshot тестируются отдельно.
  • Лимит caller учитывается до подтверждения доставки элементов: усечённый или partial ответ не должен помечать непереданные публикации как уже выданные. Это проверяется последовательностью вызовов и нормальной дедупликацией в SourceManager.
  • В Go-режиме PageMonitorSource.__aenter__, fetch и test_connection не подключаются к Python CDP. Введённый mode switch PAGE_MONITOR_SOURCE_MODE=python|go по умолчанию python; для go обязательны существующие service URL/token. Скрытого Python browser fallback нет.
  • Начальный вариант переиспользует существующее native ожидание стабильности; специальные изменения transport допустимы только как опция Page Monitor после fixture/live сравнения. Общие правила ожидания статей и Telegram не меняются. Если поздняя JS-публикация теряется, ожидание корректируется до выката; замер скорости не оправдывает потерю записей.

Как проверим ускорение

На одинаковом сохранённом HTML и одинаковых настройках — повторяемые warm измерения pure parsing отдельно от сети. На Linux — последовательный парный прогон Python/Go по трём включённым источникам с одинаковой версией браузера, selectors и лимитами. Раздельно записываются полное source wall time, получение/рендеринг, parsing, количество/порядок URL, даты, количество browser navigations, peak memory и CPU за прогон. Холодный старт браузера не смешивается с обычной обработкой.

Нагрузка и новые пороги памяти/PSI не вводятся. Успех — одинаковые публикации и даты, корректное восстановление после ошибок, отсутствие ухудшения ресурсов и измеримый результат по времени. При отсутствии выигрыша отчёт прямо это показывает; production switch не принимается как «ускорение» по факту смены языка. Необоснованное HTTP-first изменение для действующих JS-источников в этот план не входит.

Риски, восстановление и одобрение

Основные риски — различия SoupSieve/Cascadia, позднее JS-наполнение, совместимость AI learning/reparse, даты, пропуск элементов при limit/partial и лишний HTML в памяти/JSON. Их проверяют oracle fixtures, один bounded DOM, budget/size guards, snapshot sequences и реальное сравнение до PR. Неразрешённые расхождения блокируют переключение, а не прячутся Python fallback.

При rollout сохраняются pinned digests и конфигурация до изменения; восстановление — прежние app/worker images и mode=python, без удаления данных и сброса пользовательских файлов. При failed startup сначала диагностика и решение с пользователем; автоматический rollback не выполняется. .env/native token files, Readeck, общая browser инфраструктура и Assistant вне изменения.

Запрос решения: одобрить реализацию на Луне, scoped проверки с чтением трёх перечисленных сайтов и затем PR/review, CI image publication, merge и ограниченный выкат только News после успешной приёмки. Это явный запрос разрешения на перечисленные внешние действия; без него текущий этап ограничен инспекцией и этим планом.

После исполнения этот же файл дополняется фактическими изменениями, замерами, результатами проверок, ограничениями и release receipts. Сейчас production продолжает работать в прежнем режиме Page Monitor.
