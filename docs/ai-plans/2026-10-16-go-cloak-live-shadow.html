Go/Cloak: теневой прогон на реальных URL

16 октября 2026. Статус: live batch выполнен; Go release gate не пройден. Python завершил 50 заданий; Go остановлен на восьмом. Production-конвейер не переключен. Полный отчет.

Цель — проверить native Go/Cloak на ограниченной выборке настоящих публичных статей, которыми занимается production, сравнить с изолированным Python-контролем и собрать ошибки/качество/ресурсы. Рабочие маршрутизация, scheduler, AI, learning и доставка не меняются.

1. Проверенная исходная точка и варианты

Read-only проверка VPS подтвердила news_web на ghcr.io/dzarlax-ai/rss-summarizer@sha256:b6abbb428543e846d0310b86ff41236a6df028985a00ebfe4714357d22e67060 и shared infra-chrome на cloakhq/cloakbrowser:0.5.2@sha256:2c0d257802f54c4f86c9ccae336864baf63e118612732127cb96df35756a57a4. Они подключены к infra. Текущий synthetic soak находится в отдельных контейнерах и не имеет внешнего доступа. Он продолжается по своему четырехчасовому плану.

На VPS доступны nsenter, iptables, nft, ip. Снимок MemAvailable при подготовке — около 3027 MiB; это не резерв памяти и не гарантия доступной емкости к моменту запуска.

2. Выборка и работа с данными

  1. Проверить реальную схему articles/sources и взять ограниченную выборку через прямой PostgreSQL SELECT в транзакции READ ONLY, с statement_timeout=3s, lock_timeout=1s. Использовать имеющееся соединение приложения только внутри отдельного короткого export-процесса; не запускать lifespan, migrations или orchestrator.
  2. Верхняя граница — 50 уникальных публичных HTTPS article URL на порту 443, максимум 10 на hostname, за последние 7 дней по articles.fetched_at, с processing_state='completed', is_advertisement IS FALSE и sources.source_type IN ('rss','custom'). Source type не равен extraction method: выборка не доказывает покрытие всех методов.
  3. Прочитать не более 1000 последних кандидатов, ограничивая SQL-объем архивного content до существующего предела 100000 символов на запись. Дедупликация и отбор публичных URL выполняются до любой загрузки; меньше 50 доступных подходящих URL — допустимый фактический размер, а не повод ослабить правила.
  4. Исключить credentials, query string и fragment, IP literals, single-label hostnames, private/special адреса, локальные/административные URL и Telegram-message URL. Это консервативный первый subset; все исключения считаются и отражаются в покрытии. Список URL берется только из выбранных записей, без обхода ссылок и добавления случайных сайтов.
  5. Экспортировать только id, source type, URL, title, ограниченный content, publication time и необходимые media/metadata. Не копировать summary, source config, cookies, profile, full .env или ключи AI/Telegram. Доступы БД не попадают в worker/controller/gateway.
  6. Raw corpus, URL→case mapping и ограниченные результаты остаются на собственном VPS в root-only каталоге (0700/0600), максимум 64 MiB corpus и 256 MiB capture/reports. При достижении лимита — остановка, без перезаписи evidence. Локально забирается только обезличенный отчет, без URL/body/токенов. Срок хранения raw — 7 дней; timestamp истечения записывается в manifest, удаление только этого каталога выполняется при последующей явной уборке artifacts.

Архивный articles.content не считается эталоном свежей загрузки: он может быть RSS-snippet, устаревшим или прошедшим другую обработку. Отдельно учитывать различия во времени, paywall/challenge и намеренные улучшения.

3. Выделенный стенд и обязательный сетевой gate

Read-only DB export → root-only bounded corpus
                             ↓
                    isolated shadow runner
                       ↙             ↘
            Python B control     Go C service
                       ↘             ↙
                 fresh dedicated Cloak per variant
                             ↓
                 authenticated CONNECT gateway → public HTTPS

B и C запускаются последовательно, каждый на свежем выделенном Cloak того же проверенного digest, с disposable context/job и concurrency 1. Контейнеры и сети получают новый префикс news-native-shadow-; точные IP назначаются Docker и проверяются, не заимствуются у infra. Порты не публикуются, Traefik labels выключены. Действующий synthetic soak и shared браузер не используются для live URL.

Browser namespace допускает новые исходящие TCP-соединения только к точному IP/порту gateway. Отдельные control connections инициируются controller→CDP; browser не может инициировать соединения обратно к API/CDP, loopback или другим внутренним сервисам. Прямые Internet/LAN/DNS/UDP/IPv6 обходы блокируются. Для этого установить default-deny правила только внутри новых test network namespaces до запуска браузера/страниц; никакого изменения host firewall, shared namespace, host routing или сетей production. Если Docker/namespace lifecycle не позволяет доказать эту границу, live URL не запускаются.

Gateway имеет отдельный namespace с публичным egress, новым случайным токеном, отключенными EGRESS_TEST_MODE/EGRESS_TEST_ALLOWLIST, DNS-проверкой всех ответов и pinned numeric dial. На сетевом уровне также закрыть gateway→private/special/LAN/control destinations; DNS разрешить только проверенному resolver. Изолированный worker/runner не получает свободного origin egress. Не использовать synthetic CA/SPKI flags, host-resolver fixture mapping, UA/hints overrides или private-origin bypass.

До экспорта корпуса и public-origin прогонов — controlled TLS/network fixture проверки на отдельной bootstrap fixture-конфигурации (точечный test allowlist/SPKI допустим только там, без публичного egress): положительный путь proxy/TLS/JS/cookies; прямой IPv4/IPv6 и UDP/DNS bypass; private/mixed DNS/rebind; redirects/subresources/iframe/worker/WS/download/popup; loopback/control plane и proxy-auth leakage. Закрытые destinations проверяются trap endpoints и счетчиками namespace, без обращения к реальной БД/metadata endpoint. Проверять возможность реального handshake, а не только CDP rejection. Несовпадение expected deny или недоступность нормального пути блокирует запуск. После fixture gate пересоздать gateway/browser для live-профиля без test allowlist/SPKI; повторно проверить firewall traps и sanitized args. Первый выбранный публичный URL — проверка обычного certificate trust/native TLS; при ее отказе не обходить сертификаты и не запускать остальной corpus.

Прокси ограничивает TLS-трафик, не decoded response bytes; CDP filters не заменяют firewall. Эти ограничения остаются и явно входят в отчет. При необходимости менять Go policy сначала добавить regression test и повторить gate, без ослабления ради сайта.

4. Порядок запуска и ограничения нагрузки

  1. Зафиксировать текущие git revision, dirty-source manifest/SHA-256, Python/Cloak image digests, Go binary hashes и фактические limits; не обозначать рабочее дерево как опубликованный release. Компиляция тестовых бинарников в отдельном Go-контейнере допустима; Docker images на VPS не собирать, ничего не публиковать.
  2. Реализовать и проверить network fixture stand; затем получить read-only corpus. Перед новым стендом требовать MemAvailable ≥ 2 GiB. Во время теста проверять память хоста каждые 10 s; ниже 1 GiB — завершить только shadow stand и сохранить incomplete report. Текущий soak не останавливать ради емкости.
  3. Первый smoke: не более 5 URL из корпуса, сначала Go C, затем изолированный Python B на свежем Cloak. При исправном lifecycle/telemetry перейти к оставшейся выборке. Не повторять уже обработанные URL автоматически: максимум одна B и одна C main navigation на выбранный URL, общий максимум 100 navigations; page subrequests отдельно ограничены policy.
  4. Один запрос одновременно, не чаще одной main navigation в 10 s. Каждое задание ≤ 30 s; весь shadow ≤ 2 h включая setup/gates и cleanup. На 429 учитывать Retry-After, не повторять запрос; больше заданий этому hostname в текущем варианте не отправлять. В HTTP/DOM errors нет неявного Python fallback.
  5. Предлагаемые hard limits активного варианта: Cloak 768 MiB / CPU 0.5 / pids 256 / shm 1 GiB; Go либо Python controller 384 MiB / CPU 0.5 / pids 128; gateway 128 MiB / CPU 0.25 / pids 64; внешний observer при отдельном процессе 256 MiB / CPU 0.25. Read-only rootfs, bounded tmpfs/logs, без restart policy. Профиль отличается от прежнего CPU=1 benchmark; численные результаты не смешивать.
  6. Health и OOM/restart counters проверять перед/после задания; cgroup memory/CPU/PIDs — каждую секунду, idle 5/30/60 s после smoke и финального задания. Ошибка ownership/cleanup/readiness, OOM, restart или потеря обязательной telemetry останавливает вариант, без автоматического восстановления. Обычная ошибка сайта сохраняется как исход задания и не исключается из denominator.
  7. Сохранить redacted report и полный failure/exclusion ledger. Cleanup по trap/timeout удаляет только зарегистрированные shadow containers/networks, оставляя root-only evidence. До финального сообщения проверить, что контейнеры остановлены, production не перезапускался и не осталось неожиданных ресурсов.

Ни EXTRACTION_SERVICE_MODE production, ни его image/env, очередь, scheduler, source configuration и infra-chrome не меняются. AI, запись learning, reprocess и Telegram delivery в тесте отсутствуют по коду и конфигурации, а не только по флагу «dry run».

Это сопоставимый контроль, а не утверждение о полном воспроизведении production method graph. C — настоящий /v1/extract, use_browser=true, без supplied HTML/content и без synthetic readiness selector. Сравнение с архивным production content публикуется отдельно как историческое.

Фиксировать per-case state, native error/status/Retry-After, extraction method, длину и совпадение нормализованного текста, metadata/media, final URL provenance (raw только root-only), latency; отдельно source-change/expected refusal/quality difference. 6. Ограничения, риски и откат

Первый batch — выборка реальных production URL, а не непрерывное зеркало и не весь application pipeline. Неполное покрытие HTTP, Telegram-message/collections/authenticated pages, query URL, всех extraction strategies и source configs должно быть видно в отчете. Он не доказывает экономию RAM полной будущей системы: Python app остается.

Повторный browser fetch создает реальную дополнительную нагрузку на сайты и может получить изменившуюся страницу или anti-bot отказ. Полные URL и content чувствительны, поэтому raw не уходят с собственного VPS и не попадают в общий отчет. Нет обхода auth/paywall/challenge и production profiles.

Откат — остановить только runner/worker/Cloak/gateway shadow и удалить их новые сети/namespaces после bounded drain. Production не требует восстановления env, маршрутов или БД, поскольку они не изменяются. Не включать fallback при network gate failure. Rollout, публикация image, canary и постоянное зеркалирование требуют следующего конкретного решения.

7. Открытые проверки и approval gate

До запуска неизвестны фактический размер подходящего корпуса, доступность сайтов, реальная схема/семантика archived content и работоспособность namespace restrictions с pinned Cloak. Это проверки этапа, не основания ослаблять лимиты. Если нужен иной охват, например Telegram или URL с query, сначала уточнить scope.

Запрашиваемое одобрение: реализовать описанный isolated batch shadow; выполнить его network gates; сделать bounded read-only export из production DB внутри VPS; запустить ≤ 50 публичных URL в отдельных Go C / Python B окружениях с суммарно ≤ 100 main navigations; сохранить raw на собственном VPS и вернуть redacted report. Не разрешает изменения production-конвейера, AI/learning/delivery, commit/push/PR, публикацию image или новый production deploy.

После явного одобрения этого плана начать реализацию и изолированный запуск. Если gate не пройден, фиксировать blocker и продолжать только независимые безопасные проверки. Результаты и оставшиеся ограничения обновляются в этом же документе.

Контекст: native worker plan, проверки и замеры, долгосрочный план Go backend.

8. Фактическое выполнение

Python завершил 50 попыток: 3 непустых результата, 10 HTTP 403, 25 resource_limit, 10 timeout, 2 site_error. Go остановлен после 8 попыток: 7 HTTP 403 и native_browser_unavailable на case-0008; остальные 42 не запускались. Повторных загрузок не было. Точная причина сбоя пока не установлена; OOM и crash markers не обнаружены. Независимый здоровый Python-контроль завершен по правилу остановки отдельного варианта.

  • Gate news-native-shadow-f65d6c3bd3: успешная JS/cookie страница; восемь ожидаемых отказов для приватного subrequest/redirect/iframe, worker, popup, WebSocket, download и origin auth. Trap accepted = 0, origin auth leak = 0. Все ресурсы gate удалены.
  • Read-only export: 260 lightweight кандидатов, 50 выбранных URL; 206 исключены по hostname cap, 4 по общему cap. Corpus 150389 bytes, raw только на VPS; срок хранения до 23 октября 2026, 12:01:31 UTC, уборка вручную.
  • Финальные focused Python проверки shadow/benchmark: 145 passed. Linux Go: go test -race ./..., go vet ./..., go mod verify пройдены после финального изменения Go.
  • Найдены и исправлены: Unix transport для X11 вместо блокируемого IPv6 TCP fallback; shared cleanup budget 5 s вместо 2 s; best-effort stopLoading при обязательном atomic dispose и двух absence receipts; обработка Page.navigate.isDownload; sibling import для запуска mounted runner.

В этом стенде pinned browser binary запускается напрямую с аргументами из pinned image; CDP проходит через ограниченный relay UID 65534. Это изменение wrapper lifecycle относительно production cloakserve, а не полная копия production запуска. Browser UID 0 не может открыть CDP loopback; разрешение есть только у relay. Все дополнительные controller/observer/relay/namespace cgroups учитываются.

Клиентский лимит задания 30 s сохранен. Серверная очистка может выполняться независимо до 5 s; клиентский или внешний C timeout сохраняет failed row и останавливает весь вариант, без следующего задания и повторной навигации. Таймаут не доказывает недоступность самого сайта.

Первый typed main-document HTTP 403 подтвердил обычный TLS без SPKI/CA обхода. Первоначальная реализация ошибочно требовала extraction success для продолжения; после сверки с разделами 3–4 проверка исправлена на подтвержденный origin HTTP response и здоровый lifecycle/telemetry. Proxy 407, transport/policy/deadline failures не принимаются за подтверждение TLS. Повторных навигаций не добавлено.

На 12:37:24 UTC все временные live/diagnostic стенды удалены; production image/start time/restart count совпали с исходным снимком. Отдельный synthetic soak продолжается. 62 staged source hashes совпали с рабочими исходниками.

10. Отдельно разрешенный диагностический повтор

После отдельного явного разрешения выполнен один повтор case-0008 на diagnostic binary: стенд news-native-shadow-30eb166075, запрос 12998 ms, снова native_browser_unavailable и ready=false. Исходный batch report/ledger сохранен.

Контекст, конфигурация и Page.navigate прошли. Затем event_queue overflow: очередь CDP на 256 событий переполнилась, reader завершился, последующие команды и cleanup receipts получили event_overflow. Worker корректно tainted; весь выделенный стенд удален. Это подтвержденная причина диагностического повтора; точная причина первого неинструментированного сбоя остается недоказанной.

На 13:33:15 UTC production images/start times/restart counts прежние, оба контейнера работают; временных native-shadow-run containers/networks нет. Следующая работа: bounded event dispatch с работоспособными replies/cleanup при overload и synthetic flood regression; новый public run не выполнялся и этим повтором не разрешается.

11. Согласованная локальная фильтрация событий

После разрешения пользователя CDP reader фильтрует неиспользуемые события до очереди. Сохранены 16 методов, используемых обоими browser handlers; ответы команд не фильтруются. Размер 256 и fail-closed при переполнении нужными событиями сохранены. Неиспользуемые уведомления больше не обновляют activity timestamp; существующие DOM/readiness guards сохранены.

WebSocket regression с 1024 ненужными событиями до ответа команды падал до исправления и проходит после; все 16 нужных событий сохраняют порядок/session ID. Отдельно проверен bounded overload нужными событиями. Windows tests/vet и Linux offline race/vet/mod verify пройдены. Browser-dependent live tests без endpoint пропущены. Повторных обращений к сайтам, изменения рабочих binary и deployment не было; практический эффект на Cloak пока не измерен.
