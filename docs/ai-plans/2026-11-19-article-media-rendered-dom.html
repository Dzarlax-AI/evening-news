Чистые галереи и динамические изображения

Для веб-статей определять границы редакционного материала и сохранять кадры, которые появились внутри него после рендеринга. При нехватке доказательств допустима пустая галерея. Правила едины для всех доменов.

Контрольный случай РТС

У №18726 публичный API отдавал восемь изображений и MP3 с ошибочным типом «видео». Семь изображений принадлежат соседним публикациям. Из 14 сохранённых изображений фильтр убрал шесть по метке article_body_scope=outside. Остальные соседние карточки метки не получили. Первое изображение такой карточки стало обложкой.

Внутри текста РТС на месте фотографии с флагами ЕС в исходном HTML стоит маркер. Скрипт сайта загружает редакционный блок с изображением Brisel_s.jpg. В галерее и сохранённых медиа этого файла не было. og:image указывает на novac-1.jpg, уменьшенный вариант которого попал в галерею через карточку этой же статьи в боковой колонке. 1. Подтвердить путь извлечения

Локально прогнать статический HTML, сохранённый отрендеренный DOM и штатный путь с браузером. Для каждого снимка записать выбранный контейнер текста, границы галереи, источник обложки, причину запуска браузера и результат проверки AI-селекторов. Снять минимальные фикстуры до и после подгрузки блока, плюс синтетический аналог с другими именами классов и доменом.

Код подтверждает, что сейчас переход в браузер зависит от ошибки извлечения. Успешный текст может завершить этот этап даже при плохих медиа. AI-перепарсинг проверяет хеш снимка и не увидит кадр, отсутствующий в этом HTML. Какой путь сработал у конкретной записи и видит ли штатный браузер динамический блок РТС в пределах текущего бюджета, предстоит воспроизвести. Если штатный браузер не видит кадр, сначала зафиксировать причину, а приёмку восстановления кадра отложить до устранения этой причины.

2. Собрать галерею по редакционным границам

  • Определять тело по связному тексту и положению заголовка. Отмечать навигацию и группы повторяющихся карточек, включая карточки внутри общего контейнера статьи. Подтверждать связь кадра с телом по DOM и его положению относительно абзацев, подписи или редакционного figure.
  • Проверять AI-селекторы на единственном контейнере с достаточным текстом. Применять исключения и принадлежность медиа к тому же снимку. Явная принадлежность к другой карточке имеет приоритет перед широким селектором. Хост, имя файла или тематическая близость сами по себе не подтверждают принадлежность.
  • Для новых снимков публиковать подтверждённые кадры в порядке статьи. Обложкой становится отдельно подтверждённая картинка или первый редакционный кадр. og:image использовать, если подтверждена его редакционная роль на странице. При неопределённости отличать «медиа не проверены» от «редакционных медиа нет», чтобы обложка из старого списка не появлялась по запасному пути.
  • Хранить исходные кандидаты для отката. Положительные признаки распространять только на новые результаты с достаточными доказательствами. Для старых записей сохранить текущую проекцию. Сохранять подтверждённые RSS-изображения и вложения Telegram. Проверять тип source с учётом родительского элемента и MIME, чтобы MP3 оставался аудио.

3. Дать браузеру шанс восстановить кадр

Добавить один ограниченный повтор через существующий браузер для успешного текста, когда внутри надёжно выбранного тела есть признаки незагруженного редакционного медиа. Отсутствие картинок само по себе повтор не запускает. Для РТС проверить, совпадает ли результат штатного рендеринга со скриншотом пользователя. Подгрузка использует обычную загрузку страницы в браузере и действующие лимиты времени, размера DOM и параллельности. Разрешения и настройки общего браузера остаются прежними.

Рендерить только при включённом штатном браузере и в оставшемся бюджете операции. При занятости, таймауте, неполном снимке или несовпадении страницы сохранить успешный текст и уже подтверждённые медиа. Для AI-проверки использовать итоговый снимок с его хешем. Проверить, что отказ повторного извлечения не расходует новую попытку обработки статьи.

Приёмка на локальном стенде

  • РТС №18726. После рендеринга Brisel_s.jpg виден в галерее, карточки соседних новостей дают ноль кадров, обложка принадлежит статье, MP3 распознан как аудио. На статическом снимке при недоступном браузере ожидаются нормальный текст и отсутствие ложных кадров.
  • Общие регрессии. Синтетика с переименованными контейнерами и другим доменом даёт тот же результат. Blic №18559 сохраняет редакционную обложку. Статья Studenti сохраняет свои медиа, архив отклоняется. The Verge сохраняет проверенные RSS-кадры. Легитимное одиночное фото, галерея из нескольких редакционных кадров, вложения Telegram и старые записи проходят контроль.
  • Отказы и нагрузка. Проверить занятость, таймаут, неполный DOM, повторяющийся URL внутри статьи и в карточке, широкий селектор и отказ AI. Сравнить долю браузерных повторов, время обработки и пустые галереи на одном и том же корпусе до и после.
  • Запланированы go test ./... из модулей go, go-processing и go-web, затем сценарий «извлечение → запись → публичный API» на изолированном PostgreSQL. Сверить статью, ленту и мобильную галерею на тестовой выдаче. Фактические результаты этой сессии приведены ниже.

Для исторических записей возможен отдельный пробный пересчёт с сравнением «до и после».

Извлечение, повтор и проекция

  • Границы медиа определяются по связным абзацам и ближайшему заголовку. Редакционный кадр может находиться внутри текста, в редакционном figure или в блоке заголовка. Повторяющиеся карточки, чужие ссылки с заголовками и элементы навигации исключаются независимо от имени домена. Результат учитывает конкретное вхождение URL и сохраняет порядок редакционных кадров.
  • Исходные кандидаты остаются в media_files. В существующем media_evidence сохранены различие между проверенной и неизвестной областью и привязка к URL статьи. В проверенной области публикуются только кандидаты с положительным порядком editorial_order. Для записей без нового признака продолжает действовать прежняя проекция. Публичная проверка выполнена с включённым FILTER_ARTICLE_MEDIA.
  • Processing запрашивает один дополнительный рендер через существующий браузер, если успешный HTTP-разбор обнаружил редакционную вставку, ожидающую загрузки. Клиент принимает снимок той же страницы с общим текстом и новым редакционным кадром при сохранении ранее подтверждённых медиа. При busy, timeout, ограничении размера, неполном DOM и несовпадении страницы остаётся HTTP-результат. Повтор проходит внутри текущей попытки обработки.
  • Селектор анализируется на снимке с тем же SHA-256. Проверенный селектор общего контейнера не возвращает изображение из соседней карточки, даже если этот URL независимо встречается в статье.

Повтор при лимите 8 после исправления egress

В неуспешном базовом прогоне локальный прокси вернул egress_busy по соединениям с сайтом издателя, а Cloak сообщил ERR_TUNNEL_CONNECTION_FAILED для jQuery. Скрипт подстановки загрузился, но запрос за редакционным блоком не был отправлен.
