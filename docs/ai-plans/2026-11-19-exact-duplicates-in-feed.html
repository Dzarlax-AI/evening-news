Точные дубли в ленте

Редакция 2 · 19 ноября 2026 · Реализовано локально · Подготовлено к ревью

Почему обе карточки видны

Для статей №18735 и №18736 продакшен хранит два действительных наблюдения дедупликации. ID источника, исходный заголовок, текст, время публикации и хеш версии 1 совпадают. URL различаются. Лента выбирает обе завершённые статьи. ARTICLE_DEDUP_TRIAL записывает результаты сравнения, а запрос ленты ими пока не пользуется.

Что увидит читатель

При включённом фильтре веб-лента и мобильный API покажут одну карточку, если у записей совпадают источник, непустое время публикации и хеш исходного текста. Используем только наблюдения текущей завершённой попытки. Среди карточек, подходящих под фильтры запроса, показываем первую сохранённую по времени получения и ID. Для этой пары ожидаем №18735. По обеим прямым ссылкам статьи доступны.

При отсутствии точного подтверждения показываем обе записи. Поиск и дайджесты сохраняют текущую выдачу. Сравнение перефразированных новостей и истории с новыми фактами остаётся диагностическим.

Изменения

  1. Создать миграцию с ограниченной SQL-проекцией на пары подходящих статей. Web-роль получает доступ к ID подходящей статьи и её предшественников. Хеши, токены обработки и таблица наблюдений остаются закрыты. Использовать действующий индекс idx_article_dedup_exact и ограничить поиск кандидатами из того же источника с тем же временем публикации.
  2. Подключить проекцию к go-web/internal/repositories/postgres.go перед сортировкой и пагинацией. Исключать повтор только при наличии более ранней карточки, которая сама подходит под текущие условия видимости, языка, источника и категории. Стабилизировать порядок при равном времени публикации.
  3. Добавить выключенный по умолчанию переключатель web runtime через управляемый каталог конфигурации. Переключатель применяется к уже записанным наблюдениям без пересчёта, повторной AI-обработки и изменений строк статей.

Приёмка и откат

  • Интеграционный тест на локальном PostgreSQL воспроизводит пару из примера. При выключенном фильтре видны обе записи, при включённом остаётся одна. Обе прямые ссылки открываются.
  • Проверить страницы выдачи, фильтры категорий и языков, отсутствие наблюдения, устаревшую попытку, различие текста, источник и время. Если первая запись не подходит под запрос, вторая остаётся видимой.
  • Проверить права web-роли и план запроса на локальном наборе с плотной выдачей. Перед включением сверить объём потенциально скрываемых пар запросом только на чтение.
  • Откат видимости выполняется выключением фильтра web. Строки и их URL сохраняются.

Результаты проверки

На локальном PostgreSQL 17 прошли тесты обеих лент, управляемой установки, миграции и прав web-роли. Тестовый набор из 24 000 статей подтвердил индексное чтение наблюдений только для кандидатов страницы. Выключенный по умолчанию фильтр включается через HIDE_EXACT_FEED_DUPLICATES после миграции 025.

Выкладки этого изменения и изменения продовых настроек не было.
