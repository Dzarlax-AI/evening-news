Go/Cloak: cleanup при переполнении CDP

16 октября 2026 · Редакция 1 · Implemented · Локальный scope проверен

План подготовлен после Mac handoff и изолированных synthetic-проверок. Production продолжает работать на VPS параллельно прежним экспериментальным стендам. Это обязательное ограничение дальнейших испытаний, а не свидетельство свободных ресурсов VPS сейчас.

1. Цель и границы

При переполнении очереди обязательных событий завершать задание с ошибкой, сохраняя при живом CDP-соединении возможность получить ответы на команды очистки. Память, время выполнения и ownership остаются ограниченными. Никакого успешного результата после потери обязательных событий. Локальная реализация и проверки завершены; production gate остаётся отдельным.

Согласование этого плана разрешает локальную реализацию, synthetic tests на Mac и одноразовые локальные Docker-проверки без внешней сети. HTTP API, схема БД, маршрутизация Python, AI, обучение и доставка не меняются. Commit, push, PR, публикация образов, deployment и запуск стенда на VPS сюда не входят. Новые обращения к реальным сайтам требуют отдельного разрешения.

Новый проект или переписывание всего backend не создаются. Изменения Mac-проверок в native_browser_test.go, handoff-документе и untracked AGENTS.md сохраняются.

2. Проверенная исходная точка

Ветка codex/go-cloak-mac-handoff, HEAD c9441de4a6e0314a3c7073158ac960de11b9b4d3. Источники: live shadow, native worker, handoff и свежие Mac checks.

go/transport/browser.go: reader фильтрует ненужные уведомления до bounded queue на 256 сообщений. При заполнении нужными событиями он записывает prototype_browser_event_overflow и выходит. Канал done закрывается, ответы на команды больше не читаются. Этот transport используется native и обоими экспериментальными legacy-адаптерами.

nativeResources.cleanup() имеет отдельный пятисекундный бюджет: best-effort stopLoading, atomic context disposal, затем оба подтверждения отсутствия context и его targets. Ошибка очистки taint-ит worker. Текущий event consumer синхронно ожидает Fetch replies; заполненная очередь не должна блокировать эти ответы.

На Mac уже прошли восемь пакетов Go race/vet, 318 focused Python tests, 100 event-filter repeats, pinned-Cloak JS/cookie и fan-out 6 × 96 local subrequests. Исправлен только scheduling-зависимый request-budget fixture; production dispatch ещё не изменён. Linux/amd64 checks выполнялись под эмуляцией; это не native Linux race или performance evidence.

Прежний live diagnostic воспроизвёл overflow после navigate и потерю cleanup receipts. Исходная неинструментированная live-ошибка могла иметь другую причину. Старый четырехчасовой soak использовал более ранний бинарник и завершился interrupted по согласованному cutoff: 690 завершённых jobs без expectation mismatch. Его не перезапускаем и не выдаём за проверку нового filter/dispatch.

Disconnected / closedНикаких результатов или новых jobs. Не маскировать ошибку отсутствием контента.Ожидания освобождаются; потерянные receipts дают ownership loss. Соединение закрывается, goroutines завершаются.
  • Разделить сигнал terminal event failure и физическое завершение reader. Не переиспользовать один done для двух разных состояний.
  • После overload отбрасывание последующих event payloads допустимо только в явно терминальном, уже проваленном задании ради очистки. Оно не означает успешного применения policy/accounting и никогда не разрешает продолжить extraction.
  • Не увеличивать очередь событий, не создавать goroutine на каждое событие, не вводить неограниченный буфер или фоновые retries. Реализован один writer на соединение с очередью команд ёмкостью 1 и result channels ёмкостью 1; per-call writer goroutines отсутствуют. Pending command replies остаются ограниченными существующим concurrency и сроками вызовов; дубль reply не должен блокировать reader.
  • Обычные вызовы после failure быстро получают terminal error. Cleanup использует отдельный внутренний путь с узким allowlist: stopLoading, disposeBrowserContext, существующий owned-target fallback, getBrowserContexts и getTargets. Ни navigate, ни продолжение Fetch, ни DOM extraction этим путём не разрешаются.
  • Ответы уже отправленных allocation-команд необходимо дочитать в исходном bounded setup budget, чтобы сохранить полученные context/target IDs до abort и очистить их. Потеря allocation receipt остаётся ownership loss; неизвестный ID нельзя угадывать.
  • При overload native generation консервативно taint-ится даже при подтверждённой очистке: была потеря security/accounting событий. Следующие jobs не допускаются. Автоматическое восстановление или перезапуск браузера — отдельный scope. Успешный cleanup не равнозначен разрешению reuse.
  • Ошибка overload сохраняется в цепочке причин. Текущий wire error contract и отсутствие Python browser fallback сохраняются; mappings проверяются без добавления новых API-полей.
  • Оба absence receipt обязательны. При timeout, crash, generation change или отказе receipt worker остаётся unready. Foreign targets, shared browser и Browser.close недопустимы.

5. Acceptance и локальные проверки

  • 1024 ненужных события не мешают reply; все 16 нужных типов сохраняются в исходном порядке до overload.
  • Более 256 обязательных событий при заблокированном consumer дают один terminal failure. Reply после flood всё равно читается. Ни тело результата, ни успешный outcome после failure не выдаются.
  • На живом соединении после terminal failure проверяются disposal и оба absence receipts. Отказ каждого receipt, EOF и постоянный flood дают bounded failure и taint; foreign sentinel не затрагивается.
  • Отдельно проверяются allocation reply в полёте, cancel/timeout во время Fetch reply и dispose, одновременный close, late/duplicate reply и error precedence. Нет утечек pending entries или goroutines.
  • Request-budget fixture остаётся paced; overflow тестируется собственным flood-тестом. Negative control отключения cumulative guard по-прежнему должен проваливаться.

Планируемые команды на Go 1.25.6: cd go && go test -race -count=1 ./..., go vet ./..., go mod verify; focused overload/lifecycle tests повторяются 100 раз и при GOMAXPROCS=1. Проверки выполнены; фактические результаты и ограничения перечислены в разделе 8.

Python: повторить прежний focused suite service-client/comparison/replay, native benchmark/soak/shadow/corpus/gate/stand/relay с SCHEDULER_ENABLED=false, пустыми AI/Telegram credentials и изолированным DB endpoint. После Go проверок — свежий локальный pinned-Cloak smoke в --network none, synthetic HTTPS JS/cookie и bounded fan-out. Если используется CDP relay для инъекции overload, он только дополняет настоящий browser lifecycle, не подменяет DOM или HTTPS ответы. Mac-emulation остаётся compatibility evidence.

6. Отдельный Linux/VPS gate рядом с production

В этой редакции запуск на VPS не разрешается. Пользователь напомнил о совместном хосте. Это требует защитить работающий сервис и учитывать конкуренцию за CPU/RAM. Перед предложением Linux/VPS запуска подготовить конкретный короткий scope, ресурсный бюджет и cleanup; затем получить отдельное согласование. Проверки на выделенном native Linux/amd64 runner могут быть альтернативой shared VPS.

  1. Перед запуском стенда снять свежую read-only baseline: архитектура, CPU/RAM/swap и pressure, MemAvailable, cgroup production, images/digests, start times, restart/OOM counters, состояние сервиса и короткий согласованный read-only user path. Старые показатели 16 октября не заменяют эту baseline.
  2. Проверить прежний scripts/native_shadow_stand.py: пороги сейчас 2 GiB до setup и 1 GiB во время run. Это минимальные существующие guards, а не доказанный достаточный резерв. Сопоставить сумму всех container caps, shm/tmpfs, controller/observer/relay/gateway/origin/anchors и запас для работающего production с фактическими ресурсами; записать точные caps и условия остановки до запуска. Не повышать лимиты автоматически.
  3. Один новый dedicated stand, concurrency 1, уникальные labels и ownership checks; ограниченные CPU/RAM/PIDs/logs, без restart policy. Отдельный namespace, без внешней сети для synthetic stage, без подключения к production DB/CDP/volumes/env. Для проверки сетевых запретов нужен существующий Linux firewall/relay gate, а не Mac loopback smoke.
  4. Запустить native Linux/amd64 race-suite, короткие capability/HTTPS/overload проверки. Наблюдать host pressure и рабочий сервис параллельно; при превышении согласованных порогов или ухудшении production остановить только тест. Успешные test containers сами по себе не доказывают отсутствие влияния на production.
  5. Сохранить отчёт, удалить только принадлежащие стенду ресурсы. Повторить production baseline и user-path checks. Не перезапускать рабочий browser/service и не выполнять общий Docker prune, firewall flush или сетевую реконфигурацию production.

Старый soak завершён и не возобновляется. Закрытые live URL budgets и использованный diagnostic retry не продлеваются. Дополнительный public replay, более длительный soak, sizing и deployment — самостоятельные согласования после оценки результатов этого этапа.

7. Риски, откат и approval

Главный риск — спутать возможность читать cleanup replies с допустимостью продолжать задание после потери событий. Второй — потерять IDs при allocation в полёте или дождаться event consumer после его блокировки. Поэтому обязательны terminal cancellation, отдельные receipt-пути, прежние bounded deadlines и taint generation.

Число сообщений ограничено, но CDP dependency допускает крупные сообщения до application guard. Этот план не объявляет строгий byte-level memory cap; container limits остаются нужны. Непрерывный входящий flood должен закончиться закрытием соединения после cleanup budget, а не бесконечным drain.

Откат локальный: удалить только diff этой реализации по сохранённому pre-change diff, сохранив предыдущие незакоммиченные правки Mac и AGENTS.md. Остановить только свои тестовые процессы/контейнеры. Production rollback здесь не нужен, поскольку production не изменяется.

8. Фактическое исполнение и принятие

Implemented — только согласованный локальный scope. Основную реализацию и тесты выполнила Luna (gpt-6-luna). Root проверил фактический diff, запросил исправления обнаруженных границ отказа и независимо запустил integration checks. Исходные незакоммиченные Mac-изменения сохранены.

Изменены browser.go, native_browser.go, public_browser.go, owned_cleanup.go и их тесты. Сохранены event queue 256 и фильтр 16 методов. После overflow extraction прекращается, reader продолжает читать cleanup replies. Allocation receipt в полёте сохраняется; новая unsent allocation отвергается. Cleanup имеет отдельный allowlist, включая прежние detach/IO.close. Generation taint-ится даже при подтверждённой очистке; готовый HTML обнуляется при ошибке deferred cleanup.

Первый прямой context-close guard выявил регрессию обычной отмены под race: сокет мог закрыться после завершения быстрой записи. Финальное решение — один bounded writer на соединение: отмена вызова не закрывает здоровый CDP, cleanup deadline освобождает действительно stalled writer. Закрытие соединения дожидается reader и writer. Командный cleanup budget остаётся 5 секунд; собственный bounded graceful-close интервал CDP dependency дополнительный. Строгое общее wall-clock время ровно 5 секунд не заявляется.
