Что уже известно

Read-only topology 22 октября: один infra-chrome, pinned Cloak 0.5.2, все наблюдавшиеся процессы UID0, общая сеть infra. news_web использует CDP и имеет browser-control RW. Healthcheck root обращается к localhost:9222, считает FD PID1 и по marker завершает PID1. Результат и границы

Один общий Cloak, private CDP только для известных клиентов; page egress только через authenticated gateway. Worker/gateway без доступа к БД, Redis и Docker socket. DB, Redis, Traefik не перезапускаются. Не меняются схемы БД, доставки, scheduler и API аутентификация приложения. Лимит браузера не повышается.

Предлагаемое постоянное управление

  1. Root-owned systemd supervisor создаёт принадлежащие только extractor role namespace anchors; проверяет адреса/маршруты и устанавливает nft до запуска browser/relay/worker/gateway. Эти containers не должны стартовать Docker restart policy раньше supervisor при reboot. Восстановление anchor означает остановку зависимых owned processes, создание нового namespace и установку policy до повторного запуска.
  2. Browser compartment: тот же pinned Cloak, loopback CDP5100, отдельный relay UID65534 на private9222. Browser UID0 запрещены loopback control ports, прямой DNS, UDP, IPv6, metadata/private/host и прямой public egress; разрешён только точный gateway8081. NET_ADMIN и Docker socket внутри отсутствуют.
  3. Private control network соединяет news_web, worker и browser relay. Приложение сохраняет прежние infra/traefik подключения; новые стабильные role IP выделяются после проверки свежих route/Docker assignments. Relay/nft допускают только два конкретных controller IP: приложение и worker. Нельзя использовать wildcard source allowlist.
  4. Gateway имеет отдельный namespace и выход к явному resolver/public TCP443; DNS answers и CONNECT destination проверяются самим Go gateway. Worker для существующего Go HTTP пути получает только resolver/public80/443, CDP и ответы admitted app; запрещены DB/Redis/private/host адреса. Эти production policy delta требуют новых реальных namespace probes, старый synthetic receipt их не принимает.
  5. Старый root CDP healthcheck заменяется внешней проверкой из admitted worker/control role. Supervisor проверяет точные container labels/IDs, native readiness, Chrome FD и marker; marker обрабатывается после bounded drain. Перезапуск Chrome/relay сбрасывает browser generation, затем переподключает Python и перезапускает worker. Ошибка supervisor останавливает owned native processes; доступа без nft не допускается.

Файлы и последовательность

Новые reviewed deploy/news-extractor supervisor/unit/policy assets и Compose runtime overlay; необходимое зеркало canonical personal_ai_stack/deploy/news и точечное изменение только infra chrome definition/healthcheck. Никакого копирования всей infra конфигурации с Mac на VPS. Existing .env не перезаписывается; dedicated secrets генерируются на сервере и хранятся отдельно root-only.

Luna реализует production lifecycle, root проверяет дизайн/diff, независимый review проверяет restart/boot/security. Порядок: принять этот delta → устранить Python compatibility → реализовать policy/supervisor → isolated Linux same-image acceptance → PR CI/review → immutable CI images → backup fingerprints/config → drained single-browser replacement → readiness и реальные article/Telegram/Page Monitor paths → наблюдение памяти и cleanup.

Проверки

  • Real new-client→Go→Cloak article success, auth rejection, durable failure/next job, unchanged generation без browser restart.
  • Python initial/deferred navigation, cookies, auth cancellation, cancellation/owned cleanup; Telegram parser и Page Monitor fixture path.
  • Raw TCP/UDP/DNS/IPv4/IPv6/loopback/private probes denied; authenticated gateway allowed; no origin credential leak.
  • Worker exit/restart, Chrome failure, anchor replacement, supervisor failure и reboot-order simulation сохраняют default-deny до старта процессов.
  • Rendered canonical Compose с dummy values; exact image digests/healthchecks/role identities. Production acceptance: service health плюс реальный controlled article path, сохранение queue state и остальных источников.

Ни одна из новых production lifecycle проверок пока не выполнена; synthetic Go recovery и локальные routing tests — отдельные результаты.

Риски и откат

Ошибочная policy может прервать Telegram/Page Monitor или CDP, а гонка boot — открыть page egress. Поэтому scope включает весь restart lifecycle, а не единственную nft команду. До изменения сохраняются точные предыдущие app/browser digests, files, networks, healthcheck и token references. При неудаче — bounded drain, восстановление предыдущего единственного browser и сетей, затем Python routing и проверка всех клиентов. Откат не удаляет БД/volumes и не воспроизводит статьи/доставки.
