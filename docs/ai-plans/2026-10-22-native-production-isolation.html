Один общий Cloak, Go-экстрактор и Docker Compose

Редакция 22 октября 2026. Пользователь явно поручил убрать лишнее и довести существующую схему до выката с Readeck и PR/review. Это заменяет прежний вариант с host-supervisor. Разрешения на PR, CI-публикацию, merge и согласованный выкат сохраняются. Production ещё не переключён.

Что сохраняем и что убираем

Сохраняем Go API, authenticated CONNECT proxy, один общий Cloak, Python Telegram/Page Monitor, лимиты памяти и durable retries. Удаляем host systemd-supervisor, namespace anchors, Docker API reconciliation и два новых acceptance runner. Их текущие исходники, правки и доказательства сохранены в приватном архиве artifacts/compose-simplification-2026-10-22/before-simplification.tar.gz; прежние commits остаются в Git.

Целевая схема

  • Compose управляет тремя обычными сервисами: extractor, proxy и существующим shared chrome. Restart выполняет Docker; второй production browser не создаём.
  • Chrome-контейнер получает небольшой entrypoint: установить browser-only nft policy до запуска процессов, сбросить NET_ADMIN, запустить pinned Cloak и существующий relay. При выходе любого дочернего процесса или restart marker завершить оба и выйти; повторный запуск Docker снова устанавливает policy.
  • NET_ADMIN нужен только bootstrap внутри собственного network namespace. Browser и relay запускаются с пустыми effective/permitted/bounding capability sets; parent после bootstrap не имеет NET_ADMIN. На старте проверяется единственный ожидаемый private IPv4, чтобы отказать при host network или лишних сетях.
  • Browser: default-drop, без прямого DNS/UDP/IPv6/public/private доступа; только точный proxy:8081, ответы известным CDP-клиентам, relay UID65534 → loopback CDP5100. Relay9222 допускает точные адреса News и worker.
  • Worker и proxy используют обычные Compose networks: отдельная private control network и outbound network, без infra/DB/Redis. Их существующие Go URL/DNS/dial guards проверяют public destinations. Нового kernel policy для этих двух Go-сервисов не добавляем и не заявляем о такой изоляции.

Readeck и границы

Свежий read-only снимок: News — подтверждённый CDP-клиент. Readeck, bot и MCP работают; browser endpoint env у них не обнаружены. Это не доказательство отсутствия скрытой конфигурации: до переключения проверяем mounted config, код toolkit и соединения, а после — чтение Readeck/API и неизменность его контейнеров/сетей. Несовместимого активного клиента нельзя молча отключать. Assistant остаётся stopped/restart=no. БД, Redis и Traefik не перезапускаем, .env не перезаписываем, Telegram/Telegraph сообщения тестом не отправляем.

Файлы и исполнение

Luna реализует container bootstrap/health и Compose/CI packaging в отдельных файлах; root отвечает за интеграцию, удаление старой обвязки, Readeck inventory, PR и выкат. Отдельный reviewer проверяет реальный diff. Browser image основан на закреплённом Cloak digest; добавляет nftables/iproute2 и проверенные launcher/relay/X11 wrappers. Go image и API сохраняются. Старую canonical chrome service definition обновляем постоянно, чтобы обычный infra up не возвращал прежний запуск.

Приёмка

  1. Локальные scoped tests, Compose render с dummy secrets, полная Python suite и существующие Go CI checks; свежий PR review.
  2. Изолированный Linux Compose-прогон CI images: raw browser socket denial с nft/route evidence, Python initial/deferred JS/cookie и реальные parser fixtures, CoreExtractor → Go, auth rejection, тот же browser generation, cleanup.
  3. Один restart browser и один restart worker: следующая статья успешна; memory/OOM guards активны, PSI diagnostic-only. Не строим новый универсальный test framework.
  4. Merge/publish pinned images; backup canonical config/digests и свежих fingerprints. Изменить только News/Cloak. Проверить health, реальное извлечение, следующую задачу, Readeck/API и соседние fingerprints перед заявлением об успешном выкате.

Rollback и текущий результат

При отказе остановить новый browser перед возвратом прежнего, восстановить сохранённые canonical News/infra определения и точные прежние image digests, пересоздать только app/chrome. Сохранить browser-control volume; не восстанавливать БД и не перепубликовывать материалы. Не полагаемся на сохранение старого container ID: Compose управляет recreate, rollback основан на закреплённых images и конфигурации.

Старые синтетические Go/Python проверки успешны, но не принимают новую container startup схему. Host-supervisor acceptance остановлен до выката; последний прогон не получил production acceptance. Текущая редакция — реализация явно запрошенного упрощения; актуальные результаты будут добавлены сюда после проверок.
