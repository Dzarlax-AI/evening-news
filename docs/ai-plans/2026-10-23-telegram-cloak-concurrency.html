Telegram без лишней сериализации; две вкладки Cloak

23 октября 2026 · Редакция 1 · Одобрено пользователем; реализация начата на Луне. Проверки ниже запланированы, ещё не выполнены.

Цель и границы

Разрешить параллельную HTTP-загрузку Telegram и проверить ограниченный параллелизм двух браузерных операций на одном Cloak. Реализация — Luna, затем независимая проверка diff, PR и review. Production, его браузер и Readeck не меняем; merge, выкат и публикация release images в этот этап не входят. Дополнительных запросов к реальным сайтам не делаем.

Что установлено по коду

  • go/service/source_manager.go: Telegram всегда помечен как Browser; go/pipeline/source_manager.go удерживает единственную браузерную полосу на весь source job. Хотя Telegram сначала использует HTTP, соседние Telegram-каналы сериализуются.
  • go/cmd/extract-service/native_runtime.go явно запрещает browser concurrency, отличную от 1.
  • go/transport/native_browser.go хранит один active/cancel; вторая операция получает native_browser_busy. Это требует изменения управления операциями и проверки cleanup.
  • Render-обёртки имеют разные ограничения: Page Monitor использует дополнительный fail-fast semaphore; native Telegram и статьи вызывают NativeBrowser напрямую. Простая замена значения 1 на 2 непригодна.

Предлагаемое поведение

  • Telegram HTTP-стадия выполняется в общем ограниченном пуле источников (до 5), без захвата браузерной полосы. RSS продолжает работать параллельно.
  • Для native-пути единственное авторитетное ограничение захватывается при фактическом рендере и удерживается до завершения cleanup. Лишняя coarse-сериализация браузерных source jobs убирается для этого пути. Legacy backend сохраняет совместимый ограниченный режим.
  • NativeBrowser допускает конфигурацию 1 или 2, по умолчанию 1. Каждая операция имеет собственные context, target, отмену и cleanup; generation/readiness/fatal-состояние остаются общими. Обычная занятость приводит к ограниченному ожиданию с отменой, а не немедленному busy.
  • Ожидание ограничено исходным дедлайном запроса; таймер собственно browser navigation начинается после допуска. Очередь ограничена существующей ёмкостью source/RPC admission, без накопления неограниченных goroutines. Не увеличивать общий бюджет запроса скрыто.
  • Отмена либо ошибка одной страницы освобождает только её ресурсы. Потеря общей browser generation остаётся общей fatal-ошибкой; закрывать или перезапускать весь браузер нельзя.

Readeck и изоляция

На отдельном синтетическом стенде поднимаем независимый CDP-клиент, имитирующий соседнего потребителя Readeck. Он держит собственную вкладку в том же браузере; News одновременно обрабатывает две другие вкладки. Проверяем сохранность чужой вкладки, контекста, соединения и работоспособность после отмены/ошибки News. Две вкладки — лимит News, а не всех клиентов браузера. Это проверка совместимости CDP, а не полный пользовательский тест настоящего Readeck.

Production Readeck и его авторизацию не используем. Сохраняем SSRF/public URL guards, proxy/egress-путь, event/RPC bounds и запрет на глобальный Browser.close. Сетевой доступ страниц — только к synthetic fixtures.

Проверки и критерии принятия

  • cd go && go test ./... и go test -race ./...; отдельные тесты показывают перекрытие HTTP Telegram, отсутствие захвата браузера при HTTP-success, ожидание fallback и корректную отмену.
  • Реальный Cloak на synthetic fixtures: барьер подтверждает одновременную работу двух News-вкладок; при лимите 1 — строго одна. Третья News-операция ждёт и затем выполняется. Медленная вкладка не блокирует успешную вторую; отмена одной не закрывает вторую и чужую.
  • Повторяемые короткие циклы success/error/cancel, после них нет оставшихся News targets/contexts и роста незавершённых операций; RSS/HTTP работают при занятом browser admission.
  • Сравнение 1/2 при одинаковых fixtures: wall time, число активных вкладок, memory.current/anon/file, events OOM/max, рестарты и PSI там, где доступны. Browser cap 768 MiB, worker cap 256 MiB; лимиты не повышать ради прохождения. Отдельно указать вклад соседнего клиента и ограниченность измеренных пиков.
  • Mac ARM64: Go/race и доступный локальный browser smoke. Linux/amd64: build и изолированный реальный Cloak gate при наличии подходящего стенда. Эмуляцию на Mac не выдавать за native Linux. Если native-стенд недоступен — явно оставить acceptance незавершённым, без обращения к production.
  • Regression checks затронутого harness; SSRF, cleanup, generation loss и закрытие сервиса во время двух операций. CI и review без неразрешённых существенных замечаний.

Риски, откат и открытые вопросы

Главные риски: рост памяти двух страниц, гонки readiness/taint/close и двойной захват лимита. Общий browser crash закономерно затронет всех его клиентов; изоляцию этого сценария не обещаем. Если две вкладки не проходят ресурсные или lifecycle-проверки, результат фиксируем как неготовый, лимиты не повышаем. Production default остаётся 1.

Откат разработки: отмена только изменений новой ветки; чужие локальные файлы сохраняются. Настоящего production-отката в этом этапе нет, поскольку выката нет. Место доступного native Linux стенда уточняется проверкой существующего harness; использовать production browser запрещено.

Промежуточная проверка реализации

Изменения Go выполнены на gpt-6-luna / high. Native render admission: 1 или 2 активные операции, максимум 8 ожидающих; default остаётся 1. Page Monitor больше не захватывает дополнительный native semaphore; Telegram HTTP/source jobs допускаются параллельно в native-режиме. Legacy source lane сохранён.

Независимый полный GOTOOLCHAIN=go1.25.6 go test -race -count=1 ./... на Mac ARM64 прошёл во всех пакетах; vet и mod verify прошли. Linux/amd64 service/egress binaries собраны с Go 1.25.6. Синтетический harness проходит 22 локальных теста. Тесты с локальными HTTP listeners запускались вне sandbox, поскольку sandbox запрещает bind loopback.

Реальный локальный Cloak пока не принят: после приведения tmpfs к production-профилю браузер не упал, но независимый CDP-клиент получил TimeoutError до запуска worker. В более раннем меньшем tmpfs наблюдался SIGTRAP; причинность окончательно не установлена. OOM не наблюдался; все созданные ресурсы удалены. Это amd64-эмуляция на ARM64; заключение о Linux и параллелизме ожидает отдельного native CI прогона.

В PR CI добавлен отдельный native Linux/amd64 synthetic job. Первые native CI прогоны остановились на несовместимом Docker image inspect template до старта контейнеров; обвязка переведена на JSON inspection. Повторный полный Go race после исправления queued deadline и 151 Python regression test прошли. Ожидание без допуска к рендеру теперь сохраняет native_browser_busy, чтобы не расходовать попытку. App image workflow ограничен push в main, чтобы branch push с тестами не публиковал образ. Ветка и PR не меняют production-конфигурацию.
