Удаление старых Python runtime-путей

Версия 2 · 24 октября 2026 · Одобрено пользователем. Реализация на Луне завершена; финальный review и PR выполняются в изолированной ветке. База: main a5026b2 после PR #19. Посторонние локальные изменения остаются нетронутыми.

1. Результат и границы

Сбор RSS/Telegram/Page Monitor, извлечение статей и календарное планирование выполняются только существующими Go-сервисами. Удаляем дублирующие Python реализации, shadow-сравнение и Python fallback. Python сохраняет web/admin, конфигурацию источников, преобразование ответов Go, PostgreSQL persistence, durable jobs/receipts, обработку статей, AI, обучение селекторов, обогащение Telegram и доставку.

Не меняем Go API, AI, поведение браузера, его лимит двух вкладок, Readeck, production, БД и уже принятые задания. Embedded/worker execution не перерабатываем: это другая граница. Дополнительные обращения к реальным сайтам, провайдерам AI и отправка Telegram не входят в проверки.

3. Контракт конфигурации

Go collection и service scheduling становятся единственным поддерживаемым runtime. Нужны URL и токены существующих сервисов; их отсутствие должно давать понятную ошибку старта без вывода секретов. Существующие production значения *_MODE=go, SCHEDULE_DISPATCH_MODE=service, EXTRACTION_SERVICE_PYTHON_FALLBACK=false продолжают приниматься в переходном релизе, но больше не выбирают альтернативный код. Явные python/shadow и fallback=true отвергаются с указанием миграции. Не игнорировать их молча.

SCHEDULER_ENABLED=false в текущем production отключает только старый Python loop; после его удаления это совместимый устаревший ключ. Он не должен отключать Go facade, внутренний receiver или менять Go control. Реальная пауза расписаний остаётся состоянием Go-сервиса.

Новые установки больше не работают в Python-only режиме. Одновременно обновить Compose примеры, env примеры, Dockerfile и инструкции локальной разработки. Не требовать реальных production credentials для synthetic тестов.

6. Риски, откат и одобрение

Основные риски — удалить адаптер вместе со старым collector, потерять selector/cursor state, сломать восстановление старого job или новое локальное развёртывание. При обнаружении общей полезной функции сначала перенести её в узкий адаптер и проверить потребителей. Новые API/data migrations и изменение алгоритмов Go требуют отдельного решения.

Локальный откат — отдельный обратный коммит изменения, без reset чужих файлов. Production сейчас не меняется. Для будущего выката сохраняются текущие digest/config и scheduler state; удаление Python кода не разрешает переключать активные расписания назад на Python. Возможный откат приложения должен оставаться совместимым с активным Go scheduler.

Одобрение: реализация описанного Go-only cleanup на Луне, локальные и изолированные проверки, затем PR и review. Без merge, image publication и production deployment. Пользователь одобрил прекращение поддержки Python-only установки и режимов python/shadow; это явное последствие удаления старых runtime-путей, а не только удаление недостижимых файлов.
