Go Cloak: синтетическая проверка на Linux

Короткая проверка Linux/amd64 на общем VPS при работающем production. Ниже записаны свежие показатели хоста. Согласование пользователя «Го» включает локальные изменения тестового стенда, их проверки и один условный запуск синтетического стенда на VPS.

Объём и ожидаемый результат

Проверить текущий Go-код на настоящем Linux/amd64 с детектором гонок. Затем выполнить ограниченный набор синтетических проверок через закреплённый образ Cloak и локальный TLS-fixture. Через CDP-relay инъецировать переполнение очереди обязательных событий и проверить, что worker возвращает ошибку, удаляет принадлежащие ему объекты браузера, получает обе квитанции отсутствия ресурсов и помечает поколение браузера как непригодное. Проверить сетевые запреты namespace и подтвердить, что trap-listeners не приняли соединений.

В запуск не входят публичные URL, production-БД, планировщик, обработка статей, AI, Telegram, Telegraph, production CDP endpoint, production volumes и production-файл окружения. Максимум 11 попыток extraction к изолированному worker: один положительный JS/cookie case, восемь существующих отрицательных policy cases, один overload и один запрос после taint, который должен быть отклонён до новой навигации. Все URL — локальные synthetic fixtures; никаких publisher URLs.

Условия gate: предложенные лимиты 128 MiB для observer и worker не подтверждены замерами максимального потребления и могут быть слишком низкими. OOM или ошибка readiness завершает проверку; повторять запуск или увеличивать лимиты автоматически нельзя.

Лимиты ресурсов и правила допуска

Полный bootstrap native worker, вариант C, создаёт девять контейнеров. Предлагаемые пределы составляют 1 296 MiB RAM, 1,4375 CPU и 736 PIDs. Cgroup-лимиты учитывают фактически потреблённые tmpfs и shared-memory страницы; квоты mounts не прибавляются к сумме RAM. Отдельные квоты mounts: 288 MiB для девяти /tmp, 32 MiB для Cloak config/cache и 1 GiB для Cloak /dev/shm.

Допуск race-фазы: MemAvailable ≥ 3 200 MiB (1 536 тест + 128 supervisor RSS-бюджет + 1 536 резерв). Допуск browser-фазы: MemAvailable ≥ 2 960 MiB (1 296 + 128 + 1 536 MiB). Последний исходный замер — 3 415,414 MiB: запас над race-порогом 215,414 MiB, над browser-порогом 455,414 MiB.

Остановить текущую фазу при любом условии: MemAvailable ниже 1 536 MiB; memory PSI full avg10 выше 0,5%; OOM/OOM-kill в тестовом cgroup или остановка/перезапуск тестового контейнера; production health перестал возвращать 200 либо два раза подряд отвечает дольше 1 секунды; изменился production restart/OOM count; память cgroup news_web выше 222 MiB (исходные 157,5 MiB + 64 MiB) в двух замерах с интервалом 10 секунд; отказал namespace/network/ownership gate; либо истёк фазовый или общий deadline. Останавливать только контейнеры с точной меткой этого запуска и очищать их по этой метке. Эти пределы относятся к данной проверке и не являются SLA или доказательством отсутствия влияния на production.

Файлы и подготовка стенда

  • go/transport и восемь Go-пакетов: собрать и запустить race-тесты текущего исходного кода без его изменения.
  • scripts/native_shadow_stand.py: добавить короткий внутренний deadline, параметры памяти и concurrency gateway, --memory-swap равный memory limit и использование переданных Linux-бинарников без сборки application image.
  • scripts/shadow_cdp_relay.py: текущий relay только пересылает TCP и не создаёт CDP event overload. Добавить отдельный opt-in synthetic режим или тестовый harness рядом, который передаёт корректные WebSocket CDP notifications через relay, останавливается на заданной границе overflow и сохраняет только количества и квитанции, без CDP payload.
  • scripts/launch_shadow_cloak.py: уже отключает auto-update, использует аргументы pinned image и открывает CDP браузера только на loopback порту 5100.
  • tests/fixtures/native-shadow/gate_origin.py и tests/fixtures/native-cloak/origin.py: использовать только локальные синтетические TLS origins и fixture-ответы.
  • Создать новый stage с правами каталога 0700. Не использовать старый stage, его исходники, бинарники, module cache или shadow-private данные. Скопировать текущие исходники, scripts и fixtures в stage/benchmark/, создать synthetic TLS cert/key в stage/tls/, скомпилированные Linux-бинарники положить в stage/bin-soak/. До запуска записать SHA-256-манифест исходников. Экспорт БД не выполнять.
  • Метаданные старого stage подтверждают отсутствие gopath/pkg/mod/cache/download и go-cache. До запуска подготовить module cache из проверенного локального Mac cache: оставить переносимые исходники модулей, исключить Darwin toolchain и бинарники. Сверить модули с go.sum. На VPS использовать GOPROXY=off и GOTOOLCHAIN=local; скачивания и обход checksum-проверок запрещены. Если нужного модуля нет, остановить gate.

Критерии, риски и очистка

  • Race suite должна пройти на настоящем Linux/amd64 с CGO_ENABLED=1. Эмулированная Linux suite не заменяет этот результат; no-CGO запуск не допускается.
  • Overload должен пройти через CDP socket настоящего pinned Cloak и relay. Одного unit fixture недостаточно.
  • Relay injection может повредить framing или зависнуть на соединении браузера. Режим должен быть opt-in и ограничен одним запуском. Сначала локальными tests проверить framing и лимиты на loopback WebSocket fixture. Ошибка framing или ownership завершает gate.
  • Хост делит CPU и память с production. Container caps ограничивают тестовые процессы, но не исключают конкуренцию за ресурсы. Сравнить исходные показатели и повторные production-проверки.
  • Очистка удаляет ресурсы только после проверки labels. Сохранить logs/manifests в новом private stage; проверить cleanup_incomplete.json, если он появился. Не запускать общий Docker prune, не менять firewall хоста, не перезапускать production service или browser.
  • Для отката остановить только контейнеры с меткой этой проверки, удалить только её networks и новый private stage после просмотра evidence. Локальные изменения harness откатываются по сохранённому diff.
