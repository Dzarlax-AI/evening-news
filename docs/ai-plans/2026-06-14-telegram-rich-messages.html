Implementation Plan: Telegram Rich Messages for Evening News

Created 2026-06-14 for D:\Projects\Code\Personal\RSS-summuriser-1.

Task Summary

Add support for Telegram Bot API 10.1 Rich Messages to improve the Evening News channel digest formatting. The goal is to send a richer, more readable digest to the main Telegram channel while keeping the current plain HTML sendMessage path as a fallback.

Official Telegram documentation says Rich Messages were added in Bot API 10.1 on 2026-06-11 and can be sent with sendRichMessage using an InputRichMessage that contains either html or markdown.

Current Behavior

Telegram sending

news_aggregator/services/telegram_service.py sends all channel and service messages through sendMessage with parse_mode="HTML" and disable_web_page_preview=True. HTML is cleaned through validate_telegram_html().

Digest generation

news_aggregator/processing/digest_builder.py builds a compact HTML digest from DailySummary.summary_text, ordered by articles_count. It uses TelegramMessageSplitter with a configured effective limit of DIGEST_TELEGRAM_LIMIT, currently defaulting to 3600.

Full version today

news_aggregator/orchestrator.py currently builds a Telegraph payload from articles grouped by category, creates an external Telegraph page, and appends a "Полная версия: Telegraph" link to the Telegram digest when the page is available. The app also already has first-party public pages at /list and /search, backed by /api/public/feed and related public APIs.

Admin trigger

POST /api/v1/telegram/send-digest calls NewsOrchestrator.send_telegram_digest(). Scheduler tasks also call the same orchestrator method, so this change affects manual and scheduled sends.

Desired Behavior

  • Add an opt-in Rich Message path for the main news digest using sendRichMessage.
  • Keep existing service alerts and test messages on regular sendMessage unless explicitly expanded later.
  • Keep current HTML digest behavior as a reliable fallback when Rich Messages are disabled or rejected by Telegram.
  • Remove Telegraph from the digest flow and use the first-party site as the full-version destination.
  • Do not add external dependencies; use the existing async HTTP client and HTML utilities.

Proposed Rich Digest Format

  • <h2> or <h3> title for the digest date.
  • A short intro paragraph with total article and category counts.
  • A category table of contents using in-message anchors if Telegram clients render them reliably.
  • Category sections with <h3>, article counts, and separators via <hr/>.
  • Summaries rendered as paragraphs and lists instead of dense newline text.
  • Optional <details> blocks for lower-priority category detail if the message becomes long.
  • Optional media blocks only after a guarded second pass, because media URL validity and Bot API media rights need live validation.

Assumptions and Unknowns

  • Assumption: Telegram allows sendRichMessage to target the configured channel chat ID in the same way as sendMessage.
  • Assumption: Bot API accepts long rich messages beyond the regular 4096 text limit, but the exact practical limit must be tested live.
  • Unknown: how consistently current Telegram clients render <details>, anchors, tables, and media blocks in channels.
  • Unknown: whether all existing digest summary text can be safely converted to rich HTML without accidental unsupported tags or malformed entities.
  • Unknown: whether image URLs stored as primary_image or image_url are stable enough for Rich Message media blocks.

Files Likely to Change

  • news_aggregator/config.py - add feature flag such as TELEGRAM_RICH_MESSAGES_ENABLED and possibly a conservative rich-message limit.
  • news_aggregator/services/telegram_service.py - add send_rich_message(), fallback handling, and logging around Bot API errors.
  • news_aggregator/processing/digest_builder.py - add a method that builds rich digest HTML from daily summaries without disrupting the current splitter path.
  • news_aggregator/orchestrator.py - choose rich vs existing digest path, remove Telegraph generation, and append a site link instead.
  • news_aggregator/utils/html_utils.py - add a separate sanitizer/validator for Rich Message HTML tags instead of widening the existing regular Telegram HTML validator.
  • news_aggregator/services/telegraph_service.py - delete if no remaining runtime callers exist.
  • tests/ - add focused tests for rich digest HTML generation, fallback behavior, and Telegram payload construction.
  • README.md, docs/QUICKSTART.md, and Docker docs - remove Telegraph setup references and document the site link behavior.

Implementation Steps

  1. Add config fields with defaults that keep production behavior unchanged: Rich Messages disabled by default.
  2. Add a Rich Message sanitizer that allows only the tags Telegram documents for rich HTML and strips or escapes unsupported content.
  3. Add DigestBuilder.create_rich_digest() using existing DailySummary data and keeping all DB access inside the existing read operation.
  4. Add TelegramService.send_rich_message() that posts to /sendRichMessage with {"rich_message": {"html": ...}}.
  5. Add fallback: if rich sending fails, log the Telegram API response and send the current compact HTML digest with sendMessage.
  6. Wire the orchestrator so only the main digest path can use rich messages; service messages remain unchanged.
  7. Remove the Telegraph payload/read/API call from send_telegram_digest().
  8. Append a first-party site link in both rich and fallback formats, preferably to a stable daily/full digest URL if implemented, otherwise to the existing public list with suitable filters.
  9. Remove unused Telegraph configuration, dependency, service file, README entries, and docs once callers are gone.
  10. Add unit tests for payload shape, disabled feature flag behavior, sanitizer behavior, and fallback on non-200 Telegram response.
  11. After local tests, run one manual send to a service/test channel before enabling for the production channel.

Impact

  • API: outgoing Telegram API call changes only when the new feature flag is enabled.
  • Database: no schema changes expected.
  • Auth and permissions: no app auth changes. Bot must already have posting rights in the target channel; media blocks may require media-send rights.
  • Deployment: remove TELEGRAPH_ACCESS_TOKEN from required/optional runtime configuration after deploy configs are checked.
  • UX: channel posts become more structured and easier to scan; worst case should fall back to today's compact digest.

Manual QA Checklist

  • Feature flag off: manual digest send produces the same regular Telegram message path as today.
  • Feature flag on: manual digest send posts a Rich Message to a test channel.
  • Fallback: forced Rich Message API failure still sends the regular HTML digest.
  • Full-version link points to the first-party Evening News site, not Telegraph.
  • Channel post renders cleanly on Telegram desktop and mobile.
  • No category summary text is lost or visibly mangled by the rich HTML sanitizer.
  • Scheduler-triggered digest uses the same behavior as the admin button.

Risks and Edge Cases

  • Bot API 10.1 is very fresh, so client rendering may lag behind the server API.
  • Rich Message tags are not the same as regular parse_mode=HTML; reusing the current validator would silently strip the most useful blocks.
  • Large rich digests may hit undocumented or poorly documented Telegram limits.
  • Media blocks can fail if article image URLs are blocked, temporary, wrong MIME type, or Telegram cannot fetch them.
  • Generated summary text can contain characters that need escaping before embedding in rich HTML.
  • The current repository has unrelated uncommitted changes; implementation should avoid touching them and review diffs carefully.

Rollback Plan

  • Immediate rollback: set TELEGRAM_RICH_MESSAGES_ENABLED=false or remove the env override and restart the app.
  • Code rollback: revert the Rich Message and Telegraph-removal commit, restoring the current sendMessage plus Telegraph behavior.
  • Operational fallback: if rich send fails at runtime, code should automatically use the existing regular HTML digest path.
  • Config rollback: keep the previous TELEGRAPH_ACCESS_TOKEN value available outside the app until the post-deploy smoke confirms site links work.
