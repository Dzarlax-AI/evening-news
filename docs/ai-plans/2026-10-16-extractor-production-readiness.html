2. CloakBrowser — обязательная часть контракта

Проверенный образ: cloakhq/cloakbrowser:0.5.2@sha256:2c0d257802f54c4f86c9ccae336864baf63e118612732127cb96df35756a57a4; запуск cloakserve --port=9222, CLOAKBROWSER_AUTO_UPDATE=false, shm 1 GiB, лимит контейнера 768M. Свежий GET version сообщает Chrome/146.0.7680.177 и стандартный путь /devtools/browser/<id>. Wrapper и Chromium version — разные параметры.

Блокер browser cutover: Go сейчас получает ответы своим HTTP transport и выполняет CDP fulfill, а не нативную загрузку CloakBrowser. Сетевой TLS/HTTP fingerprint этим не сохраняется; прежние тесты обычного Chrome не доказывают совместимость Cloak. Dead proxy/CSP также не являются доказательством OS-level блокировки UDP/WebRTC. Не ослаблять эти защиты и не выпускать текущий browser path как эквивалент production.

CDP-discovery исправлен для DNS-имени контейнера и numeric Host; readiness использует ту же ограниченную проверку discovery JSON вместо любого HTTP 200. Seeded multiplexer routes не используются и не включаются без отдельной проверки. Нужны проверки отдельного контейнера ровно этого digest: context/session ownership, success/cancel/timeout/reconnect и FD/socket baseline multiplexer.

3. Следующий безопасный этап и варианты

Рекомендация первого пилота: Go HTTP extraction, Python сохраняет нативный Cloak fallback. У Go отсутствует CHROME_ENDPOINT; production-browser не подключается к Go. Это временная граница, а не утверждение о завершенном переносе всех browser-методов. Все R/T/C и C04 AI study остаются в Python.

До такого пилота нужно явно различать «сайту нужен native browser» и окончательный отказ: при HTTP 403/challenge/недостаточном тексте текущий rejected-path не должен молча обходить разрешенный Python fallback. Не выполнять fallback для URL admission, auth/config, превышения лимитов или отмены. Общий deadline остается один; learning/outcome фиксирует только фактически авторитетная попытка. Точное решение об upstream 429 и Retry-After проверить тестами, не превращать ограничение сайта в цикл обходных запросов.

Альтернатива полного Go browser cutover — native Cloak requests через контролируемый DNS-pinned CONNECT/egress proxy и отдельную browser network boundary, сохраняя собственный TLS браузера. Для нее нужен отдельный подробный дизайн учета wire/decoded budgets, HTTP/2, redirect, WebSocket/UDP, reconnect и согласованности browser identity. Это более широкий этап; сейчас не реализуется автоматически. Замена CloakBrowser обычным Chromium не предлагается.

4. Проверка качества и изоляция сравнения

AI secret больше не считается необъясненной ошибкой Readability: сохраненная HTTP-страница явно содержит members-only сообщение и приглашение создать аккаунт. Проверку качества не ослаблять; не считать метаданные полным текстом и не обходить доступ. Сравнить поведение Python/Cloak и Go на публично доступном материале и отдельно сохранить тип недоступного результата. Остальные реальные source/article captures проверять с происхождением и эталонными anchors, не распространять старые hash-разрешения на новые страницы.

Новые comparison-логи содержат только безопасные outcomes/methods/длины/флаги совпадения и время; actual formatter проверен. Однако shadow сейчас inline diagnostic: он может отнять до 30 секунд внутри processing deadline. Не включать inline shadow на production. Первое сравнение выполняется отдельным runner на ограниченной копии публичных заданий, без DB/learning/attempt/delivery writes. Background observer queue — отдельное возможное изменение с собственным bounded lifecycle и drop policy.

5. Стенд, память и soak

  • Отдельные Python app/Go worker/CloakBrowser того же digest и тестовый PostgreSQL; новые тестовые учетные данные, scheduler и доставка выключены, реальных AI-ключей нет. Не использовать dev Compose с общей БД и не перезапускать infra.
  • Одна Linux/amd64 машина, одинаковые jobs/corpus, byte caps, deadline, concurrency и число browser fallback. Сравнить Python-only и Python + Go + dedicated Cloak; cold/warm отдельно, три повторения и минимум шесть циклов.
  • Измерять сумму container memory/current/peak, CPU, latency, FD/CDP/owned targets, live Go heap, runtime задачи и кеши. Малый heap Go или память компилятора не выдаются за экономию полной системы. Лимиты CPU/RAM выбирать по данным; прежние тестовые 256m для Go не объявлять production sizing.
  • После коротких прогонов — изолированный soak не менее 24 часов с сохранением начального/финального baseline и профилей. Не держать непрерывный publisher load: циклы используют сохраненные fixture данные; отдельные live fetch ограничены.

До наличия совместимого CI-образа приложения и Go эта полная связка не считается измеренной. Текущий test-image A/B проверял выпуск и откат одной версии кода; это не историческая межверсионная совместимость.

6. Конкретный будущий выпуск

  1. Сверить свежий origin/main, сохранить текущие изменения, подготовить чистый diff и проверки. Commit/push/PR — только по явному разрешению. Независимое ревью и remote CI до выпуска.
  2. Добавить независимую CI-публикацию Go-образа в существующий namespace ghcr.io/dzarlax-ai; имя нового image согласуется в diff, не считается уже существующим. SHA tags и promotion по digest. Production images собираются CI, не на VPS.
  3. Подготовить reviewable Compose draft в этом репозитории; после одобрения зеркалировать в personal_ai_stack/deploy/news/. Go подключить только к infra, без published ports, Traefik labels и DB/Telegram/LLM secrets; явные CPU/RAM/admission limits. Отдельный service token одинаков у Python и Go, значение не попадает в git/логи.
  4. Сначала выпустить Python client с EXTRACTION_SERVICE_MODE=python. Отдельно поднять Go digest без Chrome, проверить private auth/ready/version/smoke. Canary включать только после утвержденных fallback semantics и source coverage. Production .env не переписывать целиком; точечное изменение секретов требует явного разрешения.
  5. Фиксировать частоту ошибок, задержку, долю fallback и результат качества. Новый unexplained content/media loss, рост retry/exhausted, OOM/restart, неосвобожденные targets или нарушение deadline прекращают расширение пилота. Числовые пороги устанавливаются по baseline перед активацией.

Откат: вернуть mode python и прежний зафиксированный digest приложения при необходимости, прежний endpoint/digest Go; дождаться bounded drain нового Go. БД не восстанавливается, повторная отправка не запускается. Shared infra-chrome и Traefik не перезапускаются. Canary rollout должен заранее разрешать этот конкретный rollback, чтобы аварийный возврат не требовал нового решения.

Главные открытые риски — native Cloak network semantics, shared processing deadline, качество недоступных/JS-страниц и непомеренная суммарная память. Независимое обновление образа само по себе их не закрывает.

8. Approval gate и текущий статус

Пользователь одобрил реализацию HTTP-only Go + нативный Python/Cloak fallback ответом «Давай». Эта реализация и изолированные проверки выполняются в рабочем дереве. Включение в production, публикация образа, commit/push/PR и изменение секретов остаются отдельными действиями; в текущем этапе они не выполняются.

Три PostgreSQL-теста прошли. Обычный Chrome не засчитывается как CloakBrowser. После automatic approval rejection пользователь явно разрешил передачу Go-исходников и синтетических тестов на свой VPS. Изолированный Cloak preflight выполнен на закрепленном digest, без сети и production-профилей: одиночный public-path тест прошел, но повторный прогон дал 1 успех и 5 отказов CDP/discovery из 6; large-DOM и repeated cleanup остаются открытыми. OOM-счетчики нулевые, причина native crash не установлена. Итоговые доказательства. Никакого обхода блокировки или production cutover не выполняется.

9. Реализовано после одобрения

HTTP-only режим принудительно включен по умолчанию в Go и в запросах Python. Go не подключается к CloakBrowser; native fallback выполняет существующий Python в пределах остатка общего бюджета. Статусы upstream, включая Reddit linked extraction, завершают граф; 429/Retry-After сохраняются. Запрещенные URL, auth/config, resource limits и отмена не переводятся в native fallback. Перед browser handoff проверяется публичный DNS; временный DNS-сбой допускает durable retry, но не обход через браузер. Connection-time гарантии Go не распространяются автоматически на переходы и subrequests Python/Cloak.

Добавлены отдельный out-of-band comparator, ручная CI-публикация только с default branch после verify и reviewable Compose overlays standby/canary/rollback. Overlay-проверки выполнены с dummy digest/token и без чтения env-файлов. Секреты, инфраструктурный mirror и production не изменены.

Свежие проверки: 429 Python tests passed, 5 явных browser/soak skips; Go Windows test/vet/mod verify/build и Linux race/vet/mod verify passed; настоящий Python → Go API smoke passed. Полный offline corpus: 72 сценария × 6 циклов, 432 пары, 0 новых расхождений и нарушений эталонов, 18 ранее проверенных различий. Новый API comparator отдельно подтвержден положительным source-content сценарием и корректным отказом при отличии Readability. Астра повторно проверила исправления без оставшихся implementation blockers.

Подробности, ограничения и файлы доказательств: HTTP-only pilot verification. Remote CI/final image, полный ресурсный baseline, 24-hour soak и активация остаются открытыми. Экономия памяти пока не измерена.
