# Go scheduler production rollout — October 23, 2026

The standalone scheduler was deployed and its first natural scheduled run was
verified on October 23, 2026. This record contains aggregate operational
evidence only; no schedule payloads, credentials, or private News records are
included.

## Release identity

- Merged change: [PR #19](https://github.com/Dzarlax-AI/evening-news/pull/19),
  squash commit `2b5ee16f1ec8f9b96d1f1b3f125f72ed5a2215f5`.
- News app image: `ghcr.io/dzarlax-ai/rss-summarizer@sha256:86c788060fde0ecde43207704b658c3b16ed7d2f3cdfb6bc4bb5bb69f624ffd4`.
- Scheduler image: `ghcr.io/dzarlax-ai/rss-scheduler@sha256:082196750b28c8563a1c11bfc720dba2d6be026c5977e01992223980eab97660`.
- Scheduler build ID: `fec7c26a38b8e101c5163bb985212f27afef5f2db6855ac84310dffd1adf5927`.

The scheduler uses a dedicated `evening_news_scheduler` database and
`scheduler_service` schema on the shared PostgreSQL 17 server. Its runtime
role owns the service schema only and is not the database owner. News and
scheduler runtime roles remain separated.

## Deployed state

- News runs in service dispatch mode with the Python scheduling loop disabled
  (`SCHEDULE_DISPATCH_MODE=service`, `SCHEDULER_ENABLED=false`). The separate
  Python worker remains responsible for executing durable News jobs.
- The Go scheduler control is unpaused. Two enabled schedules were imported;
  both due timestamps were verified against the preserved snapshot at exact
  UTC microsecond precision.
- News `GET settings` through the Go-backed admin facade returned both
  settings. An unauthenticated request using the internal app hostname was
  rejected with HTTP 401. The public home page and `/health` returned HTTP 200;
  an externally routed request to the internal endpoint received the expected
  Cloudflare HTTP 302.
- The scheduler has no public port or public route. Its News target remains the
  statically configured internal `news-worker` alias.

## First natural scheduled execution

The first natural Go-scheduled collection completed around 20:51 UTC. It
fetched 14 articles, processed one, and reported zero errors. Inventory showed
one receipt, one accepted scheduler outbox occurrence, and one successful
News job, with no duplicate acceptance or pending occurrence afterward.

At the post-run observation, the new Go scheduler used about 5.8 MiB, the web
process about 101.5 MiB, and the worker about 86.2 MiB. These are individual
point-in-time readings, not peak memory measurements or capacity guarantees.
The new web, worker, and scheduler containers had zero automatic restarts and
zero OOM events. Browser, Readeck, extractor, egress, and PostgreSQL container IDs,
start times, and restart counts remained unchanged.

Local rollout fixtures were cleaned up. The protected snapshot remains on the
private deployment host; no production records were exported to external
artifacts. See the [scheduler operations guide](README.md) for ongoing health,
configuration, and rollback procedures.
