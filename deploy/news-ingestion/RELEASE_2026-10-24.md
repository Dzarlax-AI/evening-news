## Deployment

Only web/executor images and their new ingestion client configuration changed;
the private `news_ingestion` service was added. The existing Go job-worker
container and image were retained, with a controlled stop/start after queue drain.
Scheduler dispatch was paused through revision-protected control, then resumed.
Schedule revisions and due instants were preserved.

Migration `012_article_ingestion` ran through normal application startup against
PostgreSQL 17.11, database `aistack`, schema `news`. The runtime role has six
connections maximum (five pooled and one dedicated lock), column-scoped article
writes, no queue updates, and no article deletion. Its fence function belongs to
a separate non-login role.

Existing eight environment files were preserved byte-for-byte. New secrets were
generated on the server and remain in root-only files. A verified custom-format
News-schema backup, original Compose, fingerprints, and diagnostics are retained
in the server's protected rollout directory. No database restore was performed.

The shared browser, Readeck, collector, scheduler container, PostgreSQL, egress,
and Traefik were not recreated or reconfigured. Their fingerprints are checked
against the pre-deployment snapshot.

## Acceptance

Public home, feed, and health returned HTTP 200. Web, executor, ingestion, and
worker were healthy. Ingestion health returned 200 from executor; an
unauthenticated ingestion API request returned 401. The worker acquired a fresh
lease (generation 8). Docker reset its old restart counter from two to zero
during the deliberate start; compare subsequent observations with that new baseline.

The first scheduled job at 14:51:33 UTC failed before saving articles:
`source_commit_failed`. PostgreSQL rejected a metadata update of an existing
article because its right-hand expression reads `hash_content`, which was
missing from the runtime role's column SELECT grant. The earlier fixture covered
new inserts but missed this existing-article update path.

The minimal additional `SELECT(hash_content)` grant was independently reviewed,
reproduced with a no-row UPDATE, and validated with a temporary grant inside a
rolled-back transaction before it was applied permanently. Queue mutation and
article deletion remain denied. No image or service restart was required.

The follow-up synthetic Docker gate `9f5aea5b0185` passed all 15 checks with
the exact operator role SQL. It seeds an unprocessed duplicate and verifies
that ingestion updates the same row, replaces stale content, populates a
64-character hash, and records `updated=1`. It uses internal fixture networking,
fake AI only, no real messaging or production origins, and reports zero restarts
and cleanup errors. All nine focused gate contract checks and independent review
passed. Application binaries are unchanged by this grant correction.

## Recovery

Preserve new articles and additive tables. A recovery decision must be explicit:
pause dispatch, drain/fence execution, restore the recorded application Compose
and old image digest with Python collection mode, then resume the previous worker.
Do not restore the database over new data, delete volumes, or restart the browser
or Readeck as part of this release.
